# I12 迭代设计：卖出侧证据闭环——信号驱动卖出与持仓复评

> 排定：2026-09-05。状态：**已实现并验收（2026-09-05，含 I12.1 网格扩展与三期证据运行记录）**（拍板记录见 §八）。
> 本源对齐（沿用）：**自己先用 · 核心价值=实用 · 接受"未经实证"但绝不自欺**。
> 直接依据：`docs/策略研讨-全景与第三阶段方向-2026-09-05.md` §三/§五第 1 优先；`docs/策略迭代-第一性原则-v1.md` §2「被评估对象必须与实际使用对象一致」与 §5 撤回条款。
> 代码事实核对日期：2026-09-05（引用函数名与代码位置，行号易漂移不引用）。

## 一、问题定义：三个代码事实

1. **信号侧永不产出卖出 action**：`action_from_score` 只有 强烈买入/买入/观望 三档，`apply_signal_policy` 只降不升。后果：`QushiV5Adapter._ACTION_TO_DECISION` 的卖出键是死键；`_close_screen` 生成的 sell_queue 恒空；`_check_positions` 的 REASON_SIGNAL 分支是死路径。引擎 sell_signals（突破多头止损、OBV/主力流出、momentum ⚠️）只是文案，不参与评分与 action。
2. **卖出规则零回测评估路径**：`replay.py` 只对 `BUY_ACTIONS=("强烈买入","买入")` 落信号；`stats.simulate_signal` 只有 stop/target 两种出场。exit_check 四规则（涨停开板/跌破MA20/高点回撤3%/尾盘放量3倍）、static stop/target **从未被任何评估覆盖**——第一性原则 §5「若过滤后没有稳定增量，撤回」对卖出规则无法执行，因为它们从未被测量过。3% 高点回撤更是外部文章的拍定值，未经本项目实证（外部对照样本 082 用 25% 宽回撤）。
3. **持仓退出无与买入同源的证据链**：账户退出 100% 依赖价格防线；「基本面走坏了该卖」这件事——买入打分器明明每天都在算——没有任何制度化出口。

## 二、为什么必须现在做

- 证据积累期的每一期滚动评估都在为后续决策供料。买入侧口径已收敛（I10），但**被评估集合缺了半边**：持仓规则（退出）不在评估范围内，等于用一半证据回答全局问题。
- 融合一阶段落地四条退出规则时未预承诺评估路径（默认开、无回测），与本迭代同源的教训是：**先通评估，再开规则**。本迭代把顺序反过来执行。
- 模拟账户已有 I11 持仓归因，能回答「卖了之后谁贡献/拖累」；缺的是「该不该卖」的证据。

## 三、范围内 / 范围外

**范围内**

1. **重放日度台账**：`daily_actions.jsonl`（每日 raw/final action + score + confidence，无前视）；
2. **卖出规则模拟器与对照报告**：baseline / strict_final / strict_raw / confirm2 / time_stop 五变体并列披露（纯披露，不设门槛）；
3. **账户层信号卖出**：close screen 持仓全保真复评 → 复用 sell_queue 执行路径；`SIM_SIGNAL_EXIT_MODE` 默认 off；
4. **时间止损**：exit_check 第五规则（持有 N 交易日未达 +1R → 卖出），默认 off；
5. results.csv 增 `exit_rule` 列；trades note 标注信号卖出与时间止损原因。

**范围外（明确不做）**

- 不改买入侧任何规则与 SCREEN_GATE 门槛（SCREEN_GATE 仍是买入侧门；卖出侧本迭代**只披露不设门**）；
- 不删 `_ACTION_TO_DECISION` 死键（行为冻结；单列清理项，见 §八 Q4）；
- 不做卖出冷却期/涨停黑名单（外源 078/116，列为后续候选）；
- 不做换仓迟滞、波动率仓位缩放（研讨报告 B6/B3，各自单独立项）；
- 不做乖离率动量等买入侧口径变更（B7，与卖出侧耦合评估会互相污染归因）；
- 不做参数寻优；五变体参数全部预承诺进 `backtest/config.py`。

## 四、模块设计

### 4.1 重放日度台账（`backtest/replay.py`）

- 重放已对每只股票每个交易日滑动窗口跑 `run_analysis` → `signal_to_dict` → `apply_signal_policy`，只是只落盘买入侧行。本迭代**零新增计算**，把每个截窗的结果追加写入快照目录 `daily_actions.jsonl`（与 `signals.jsonl` 并列，既有消费方零改动）；
- 行字段（精简）：`date, symbol, raw_action, final_action, veto_reason, score, confidence, policy_version, policy_hash`；
- 缓存失效复用现有机制：cache 条目带 `policy_hash`，不匹配 → 该股重算并同批重建台账（口径变更一次性重算，报告披露规模）；
- 存量快照无此文件 → 卖出对照小节标「需重放」，不阻塞既有统计（legacy 隔离沿用 I10 模式）；
- 体积估算：60 只 × ~500 交易日 × ~150B ≈ 5MB 量级，可接受。

### 4.2 卖出规则模拟器与对照报告（`backtest/stats.py` + `report.py`）

对每个既有买入样本（入场=信号日 T 的 T+1 开盘，与现行口径一致），以台账对齐 T 之后每个交易日：

| 变体 | 触发定义 | 出场 |
|---|---|---|
| baseline | 现行口径：stop/target 扫描 + `SIM_HORIZON` 收盘兜底 | 现行 |
| strict_final | 首个 `final_action ∉ SIGNAL_BUY_TIERS` 的台账日 S | S+1 开盘 |
| strict_raw | 同上，但以 `raw_action` 判（隔离市场门/趋势门，回答「纯动量维持退出」的独立价值） | S+1 开盘 |
| confirm2 | final 口径**连续 2 日**出买入档才触发 | 第 2 日 S+1 开盘 |
| time_stop | 自入场成交日起持有 ≥ `SIM_TIME_STOP_DAYS` 个交易日且 (现价−entry)/(entry−stop) < `SIM_TIME_STOP_MIN_R` | 触发日收盘 |

- 兜底不变：未触发信号卖出的样本仍走 baseline 出场——**信号卖出是"提前离场"，不是替代**；
- 与价格触发同日冲突时**价格规则优先**（预承诺，避免规则间套利；现行「同日双触保守记止损」不变）；
- T+1 与跌停顺延沿用现行机制（`EXIT_POSTPONE_LIMIT` 内顺延，超限 forced）；
- **报告**：`report.md` 新增「卖出规则对照」小节——五变体 × {n、已实现单笔收益均值/中位、胜率、平均持有交易日、超视界占比、触发原因分布}，并列 r20/r60（入场锚定）作参考；n<10 标「⚠样本不足」；只披露不做显著性断言；
- `results.csv` 增 `exit_rule` 列（signal_final/signal_raw/signal_confirm/stop/target/horizon/time_stop）。

### 4.3 账户层信号卖出（`server/sim_strategy.py` + `server/sim_service.py`）

- 新参数 `SIM_SIGNAL_EXIT_MODE`：`off`（默认，零行为变化）| `strict_final` | `strict_raw` | `confirm2`；
- **落点 = `_close_screen`（close_nextday 模式 15:05 收盘定档）**，评估集 = 扫描宇宙（现状）+ **全部持仓**：
  - 持仓评估**强制全保真**：不做无资金流两阶段初筛，直接带资金流重跑引擎+后处理（持仓每日 ≤5 只，成本可忽略；卖出侧宁可信其有）；
  - adapter 新增 `signal_exit_reason(final_action) -> Optional[str]`：按 mode 判定持仓是否该卖（策略专有逻辑集中 adapter，遵守 v6 解耦纪律；账户内核 `sim_account.py` 零改动）；
  - 判定卖出 → 持仓 symbol 进 sell_queue（note=`signal_exit`），**复用既有次日执行链**：跌停顺延、`EXIT_POSTPONE_LIMIT`、trades 记 REASON_SIGNAL——现有死路径由此转活，不新发明执行通道；
- **confirm2 状态**：连续计数存 `data/sim/state.json` 新键 `strategy_state.signal_exit_streak`（symbol → {last_date, streak}；键可选，旧 state 兼容读）；
- **intraday 模式限制**：信号卖出仅支持 close_nextday（收盘确认纪律，不做盘中噪声复评）；intraday 模式配了非 off 时启动披露「信号卖出不生效」，时间止损不受此限；
- **优先级总序**（`_check_positions` 与 sell_queue 一致）：static stop → static target → exit_check 四规则 → 信号卖出 → 时间止损；同日多规则命中取最先者，note 记录全部命中原因；
- `_ACTION_TO_DECISION` 死键与扫描宇宙 sell 分支保留原状（引擎仍不产出卖出 action，扫描侧 sell_queue 依旧恒空——卖出语义只存在于持仓复评）。

### 4.4 时间止损（`QushiV5Adapter.exit_check` 第五规则）

- 新参数 `SIM_TIME_STOP_DAYS`（0=off）、`SIM_TIME_STOP_MIN_R`（默认 1.0）；
- R = (现价 − entry_price) / (entry_price − pos.stop)；持有交易日数 ≥ N 且 R < MIN_R → 卖出 `time_stop`；
- 与信号卖出无耦合（纯价格/年龄规则，确定性输入，盘中可判）；回测侧（4.2 time_stop 变体）与账户层共享同一组预承诺参数，保证被评估对象=使用对象；
- 交易日口径边界（含买入成交当日与否、跨停牌）在测试中固化。

## 五、口径声明（硬约束）

1. **默认全关零影响**：`SIM_SIGNAL_EXIT_MODE=off`、`SIM_TIME_STOP_DAYS=0` 时，模拟账户行为与改动前逐字一致（验收 A6）；
2. **卖出侧只披露不设门**：SCREEN_GATE / advise / 候选验证完全不动；卖出规则的门（若有）必须待对照报告积累 ≥2 期滚动评估证据后单独立项；
3. **预承诺参数进 `backtest/config.py`**：五变体参数一次写死，调参走矫正器四类动作留痕；
4. **无前视**：台账 S 日字段仅由 ≤S 日数据决定；信号卖出判定用收盘定档数据（close_nextday 15:05）；
5. **出场不对称**：入场可要求周 K 确认（require_weekly），出场**不要求**——退出应快于入场，这是规则设计的本意，报告如实披露；
6. 账户内核 `sim_account.py` 不 import analysis/（v6 解耦纪律）；信号判定逻辑全部在 adapter；
7. 披露纪律：n<10 ⚠样本不足；对照报告不宣称胜率改善；自用参考非投资建议。

## 六、验收标准

- **A1 台账无前视**：构造测试——修改 S 日之后的 K 线，台账 S 行逐字不变；
- **A2 台账与 signals 同源**：同日同 symbol 的 raw/final/score/confidence 与 signals.jsonl 买入行逐字一致；
- **A3 policy_hash 失效传导**：改 `signal_postprocess` 一行 → 台账随缓存失效重算，报告头更新；
- **A4 模拟器手算复核**：strict_final / strict_raw / confirm2 / time_stop 各构造触发与不触发用例（含 T+1 边界、跌停顺延、与 stop 同日冲突价格优先）；
- **A5 对照报告**：五变体全列、n<10 ⚠、legacy 快照标「需重放」、exit_rule 落 results.csv；
- **A6 账户默认零变化**：新参数全 off → 全量回归绿，一轮 close screen 产出与改动前逐字一致；
- **A7 信号卖出激活链**：off→strict_final 构造用例——持仓复评观望 → sell_queue 入队 → 次日成交 → trades note=`signal_exit`/REASON_SIGNAL；confirm2 需两日才触发、中断一日重置；
- **A8 时间止损边界**：R 恰等于 MIN_R 不触发（严格小于）、交易日计数、停牌跨日；
- **A9 全量回归**：`python run_all_tests.py` 全绿。
