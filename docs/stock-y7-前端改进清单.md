# stock-y7 前端改进清单

> 依据：2024 实机运行验证 + 前端代码逐行走查（app.js 4444 行 / index.html / style.css / glossary.js）。
> 每项含【问题 → 证据 → 修法 → 工作量】。行号基于当前 main 分支 b5b06c6。

---

## P0 —— 安全与致命可用性（建议立即做）

### 1. 封死 XSS 注入面 🔴
- **问题**：搜索候选把 `s.code / s.name` 未转义拼进 innerHTML **和 onclick 属性**；K线悬浮提示用未转义的 `found.title/formula/desc` 注入 innerHTML。
- **证据**：`app.js:1975-1978`（搜索）、`app.js:677-681`（tooltip）、`app.js:2022` 等多处 `onclick="analyze('${symbol}')"` 字符串拼接。
- **修法**：
  - 所有动态文本过 `escHtml()`（项目已有该函数，但覆盖不全）；
  - `onclick="..."` 内嵌字符串拼接改为 `data-*` 属性 + 事件委托；
  - 加一条代码规范：innerHTML 模板变量必须经转义。
- **工作量**：0.5～1 天

### 2. ECharts 本地化，消除白屏单点 🔴
- **问题**：唯一外部依赖 `cdn.jsdelivr.net/npm/echarts@5.5.0`（index.html:7）。jsdelivr 在国内时好时坏，脚本阻塞加载失败 → 整页白屏且无提示。
- **证据**：`index.html:7`；`app.js` 全局依赖 `echarts` 对象。
- **修法**：把 echarts.min.js 下载到 `dashboard/vendor/` 本地引用（项目本来就 vendor 了 requests，风格一致）；或至少 `<script onerror>` 降级到备用 CDN 并显示「资源加载失败」横幅。
- **工作量**：0.5 小时（本地化方案）

### 3. 请求超时与静默吞错 🔴
- **问题**：analyze 的 fetch 无 AbortController/超时，网络卡死时用户无限等骨架屏；扫描进度轮询 `catch(()=>{})` 静默吞错、无限轮询，后端挂了用户毫无感知。
- **证据**：`app.js:2051`（analyze 无超时）、`app.js:4228-4247`（扫描轮询吞错，4241）。
- **修法**：
  - 统一封装 `fetchWithTimeout(url, ms=15000)`；
  - 扫描轮询记录连续失败次数，≥3 次显示「与服务器的连接中断 [重试]」；
- **工作量**：0.5 天

## P1 —— 清晰度（对应用户核心疑问："是不是不够清晰"）

### 4. 收敛信息架构：去重复入口 + 改名 🟠
- **问题**：
  - 侧边栏 7 个分区（自选/历史/一览/档案/核心池/速递/扫描档）与 wp-panel 里第二套 5 个 tab（历史/一览/信号档案/核心池/每日速递）功能重复、双入口两套激活逻辑；
  - 「档案」vs「历史」语义不可分；「一览」vs「核心池」都是多股列表。
- **证据**：`index.html:49-56`（侧边栏 tabs）vs `index.html:69-75`（wp-panel tabs）。
- **修法**：
  - 删除 wp-panel 重复 tab，只保留侧边栏单入口；
  - 改名：「档案」→「信号档案」、「历史」→「浏览记录」、「一览」→「多股行情」，并在每个分区头部加一句 12px 说明文字（如"信号档案：分析产生的买卖信号自动留档，含后续涨跌验证"）。
- **工作量**：1 天

### 5. 错误文案人话化 🟠
- **问题**：后端原始错误直接展示给用户。实测无效代码返回 HTTP 200 + `"K线数据不足: 0条"`，前端原样贴进结论卡。
- **证据**：`app.py` analyze 接口；`app.js:2058-2059`。
- **修法**：后端返回结构化 error code，前端映射为人话：
  - `kline_empty` → "没有找到该代码，可能输错了或已退市，试试搜索框输入名称";
  - 网络类 → "行情数据源暂时连不上，稍后再试"。
- **工作量**：0.5 天

### 6. 补齐术语词典 🟠
- **问题**：glossary.js 只有 14 条。副图指标 MACD/RSI/KDJ/BOLL/WR 全部无解释；「量能/多头排列/金叉死叉/唐奇安通道/背驰/海龟法则」等正文高频词缺失。
- **证据**：`glossary.js:10-79`；副图按钮 `index.html:118-125`。
- **修法**：补 20~30 条（重点：五个副图指标各一条"是什么+怎么用+局限"；策略系统词若干）。小白模式下指标按钮旁加 ？ 图标。
- **工作量**：0.5～1 天

### 7. 风险大白话全覆盖 🟠
- **问题**：只有命中 risk_codes 结构化码的风险才翻译成大白话；`risk_notes` 原文黑话直接漏出（如 ATR、OBV 字样）。
- **证据**：`app.js:1549-1551`（原文直出）、`1268-1293`（RISK_EXPLAIN 仅 8 条）。
- **修法**：短期前端补映射表兜底；长期让后端 risk 输出全部结构化（code + params），前端统一渲染。
- **工作量**：1 天（前端版）/ 2~3 天（前后端结构化）

### 8. 移动端恢复小白模式切换 🟠
- **问题**：≤420px 时 mode-toggle 整组被隐藏——手机上无法切到小白模式，与 v4.2 "小白友好"目标直接矛盾。
- **证据**：`style.css:918`。
- **修法**：小屏保留模式切换（可缩为图标）；顶栏其余项折叠进"更多"菜单。
- **工作量**：0.5 天

### 9. 新手引导 / 空态设计 🟡
- **问题**：首次打开只有一句"输入股票代码开始分析"，不知道"扫描买入""速递""方向一致率"是干嘛的。
- **修法**：首次访问（localStorage 标记）显示 3 步引导浮层：①搜一只股票 → ②看右侧"AI 结论+操作计划" → ③用"扫描买入"找机会；各分区空态配一句话用途说明。
- **工作量**：1 天

## P2 —— 工程质量与体验打磨

### 10. 可访问性（a11y）🟡
- 全项目无 aria/role/tabindex；页签无法键盘导航；#666 文字配深底对比度偏低。
- 修法：sb-tab/wp-tab 加 `role="tab"`+键盘左右键；卡片折叠头加 `aria-expanded`；正文对比度提到 4.5:1。
- 工作量：1～2 天

### 11. 自选/分组数据上移服务端 🟡
- localStorage 换设备即丢（设置里仅提示导出备份，index.html:259）。
- 修法：仿照 pool.json 模式存 `data/watchlist.json`（单用户场景足够），localStorage 只做缓存；保留导入导出。
- 工作量：1 天

### 12. 顶栏减负 🟢
- logo+搜索+5 热门+扫描+3 按钮+自选+历史+行情条挤一条（index.html:12-40），小屏横向滚动严重。
- 修法：热门股收进搜索框聚焦时的推荐面板；「扫描买入」移入侧边栏扫描档分区头。
- 工作量：0.5 天

### 13. app.js 模块化拆分 🟢
- 4444 行单文件，渲染/状态/网络/XSS 面耦合。
- 修法：按域拆 ES modules（api.js / chart.js / watchlist.js / journal.js / scan.js / ui.js），index.html 引入 type="module"。
- 工作量：2～3 天（需回归测试）

### 14. 渲染性能微调 🟢
- K线 mousemove 高频 convertFromPixel 无节流（app.js:630-674）；refreshQuote 每 2s 全量重算 MA。
- 修法：mousemove 加 rAF 节流；MA 用增量计算或降低重算频率。
- 工作量：0.5 天
