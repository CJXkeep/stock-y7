# 版本路线图：v5.0「自用投研助手」

> 状态：已按本源确认重写，迭代顺序已排定（2026-08-21）；同日按 v5 设计第三轮 review 修订口径（动作枚举对齐代码 / 挂点位置与映射修正 / 重放滚动窗口 / 日志全量落盘）
> 本源定位（用户确认）：**自己先用 · 核心价值=实用 · 接受"未经实证"但绝不自欺**

## 一、版本目标（一句话）

把工具变成"**自己看得懂、信得过、用得顺**"的投研辅助：用轻量历史回测防止自我欺骗，用真实信号日志积累诚实样本，用实用打磨提升日常体验。

## 二、背景与依据

- 五模块策略 + 缠论日/分时已正确性修复完毕（41 个回归测试全绿）；
- 审计报告（docs/策略审核报告.md）：策略未经样本外验证，盈利能力未知；
- 本源对齐（用户确认）：自己用、要实用、接受"未证实" —— 本版**不追求研究级完备**。

## 三、范围内 / 范围外

**范围内**
- Git 基线与统一测试入口（轻量，防手滑/可回滚）；
- **信号日志**：真实信号发生时**全量落盘**（动作枚举照代码：强烈买入/买入/谨慎买入/观望；含 breakout 多头止损与空头平仓，按修订枚举归类），去重窗口内的重复信号标 `deduped`、过滤在展示/统计层做，事后补记 5/10/20/60 交易日走势；
- **核心池管理**：可视化选择/维护、持久化、随时可换（回测与信号日志共用）；
- **历史信号统计**：核心池 × 2–3 年日线，每个买入侧信号（强烈买入/买入）之后的 5/10/20/60 日表现（胜率 / 平均收益 / 期望）+ 可选单信号独立模拟；
- 实用打磨：启动/加载/刷新、核心列表管理、导出/复盘。

**范围外（明确不做）**
- 组合级持仓/权益模拟、资金管理、仓位模型（评估的是信号质量，不是自动交易收益）；
- 大样本分层 / 消融矩阵 / bootstrap CI / 滚动窗口；
- 实盘对接、对外分发；
- 外部历史分钟数据（分钟缠论不做历史回测，由信号日志覆盖真实分钟信号）；
- 任何"盈利能力"宣称。

## 四、迭代划分（顺序已排定，每个迭代 = 一个 Comet change）

### I7.1 `git-baseline-and-test-runner` — 工程基线
Git 初始化、`.gitignore`、首次提交标记 `v4-baseline`；`run_all_tests.py` 一条命令跑全部测试。
**验收**：一条命令全量回归通过；此后每次改动有 diff 可查、可回滚。依赖：无。规模：小。

### I7.2 `signal-journal` — 信号日志（成本最低见效最快）
信号发生时落一条记录（挂点在 app 后处理**之后**，记录最终 action；signal_type 枚举：buy / strong_buy / cautious_buy / breakout_exit / short_cover / chanlun_buy1·2 / chanlun_sell1·2，映射见设计稿 §5.4）；**全量落盘不丢弃**——去重窗口内重复信号标 `deduped: true`，过滤在展示/汇总层做（与历史统计共用 dedupe.py）；并发写持线程锁；分钟/盘中信号收盘后回填 `trigger_close`；事后自动补记 **5 / 10 / 20 / 60** 交易日价格与收益；`/api/scan` 扫描结果不入档；看板新增"信号档案"面板。
**验收**：真实信号全量持久化、deduped 标记与窗口过滤正确、谨慎买入/空头平仓按修订口径落档、补记正确、汇总可用；纯本地数据。依赖：I7.1。规模：中。

### I7.3 `core-pool-manager` — 核心池管理（可配置 + 可视化 + 随时换）
看板提供核心池管理界面（从搜索/自选股勾选加入、删除、排序、重命名），持久化到后端 `data/pool.json`；池变更即用于信号日志筛选与回测快照。
**验收**：池可增删改查并持久化、version 每次变更递增（快照失效提示的完整闭环在 I7.4 快照落地后生效，I7.3 只需埋好 pool.version 关联）。依赖：I7.1。规模：中。

### I7.4 `historical-signal-stats` — 历史信号统计
核心池快照（20–40 只 + 沪深300）→ 重放式信号生成（复用 run_analysis，无前视，预热标记；**滚动截窗与实盘同构：个股最近 250 根、指数最近 60 根**；重放为原始输出、不含 app 后处理，报告头披露该口径）→ 信号去重 → 统计每个买入信号的 5/10/20/60 日 forward return（胜率/平均/期望，按股票/年份拆分）+ 可选单信号独立模拟（stop/target/无触发）。
**验收**：核心池 2–3 年可生成历史信号并可复现；无前视探针、重放窗口与实盘一致性（250/60 根）、去重、统计手算复核通过；输出 CSV + 汇总表。依赖：I7.1 + I7.3。规模：中大（一次性投入）。

### I7.5 `usability-polish` — 实用打磨
体验项：启动/加载/刷新、核心列表管理增强、信号档案导出、看板信息密度。
**验收**：清单各项落地且不回归。依赖：I7.2/I7.4。规模：中。

> 顺序理由：I7.1 打底 → I7.2 最快见效（日志先跑起来）→ I7.3 提供可维护的核心池 → I7.4 历史信号统计依赖池 → I7.5 收尾打磨。I7.2 与 I7.3 逻辑上相互独立，但**都会改动 app.py 与 dashboard/index.html**，且本流程不做分支隔离——若真并行需预期手工合并，默认建议按 I7.2 → I7.3 串行执行。

## 五、v5.0 完成定义（DoD）

1. 信号日志（5/10/20/60 视界）在真实使用中持续累积并可查看汇总；
2. 核心池可视化维护、持久化、变更可追溯（快照失效提示）；
3. 历史信号统计对核心池可运行、可复现、无前视，输出胜率/平均收益/期望/笔数（含单信号模拟，可选）；
4. 全量回归通过，全程在 Git 管理下；
5. 日常体验项完成，不引入研究级负担。

## 六、风险与开放问题

| 风险/问题 | 缓解 |
|---|---|
| 回测笔数少、置信度有限 | 报告标注笔数；信号日志长期补足 |
| 免费源历史质量 | 快照校验 + 与信号日志互相印证 |
| 自用也自欺 | 无前视 + 快照 + 真实验证三保险 |
| 核心池变更频繁 | 池版本化：变更后快照失效，重新生成才可回测 |
| 信号日志钩子影响主流程 | try/except 隔离，落盘失败只 log |
| 重放与实盘口径漂移（窗口长度/后处理差异） | 重放滚动截窗与实盘同构（250/60 根）；原始 vs 最终动作在报告头并列披露 |
| 并发请求同时触发日志钩子 | 进程内线程锁保护 journal 追加写 |

## 七、v6.0 展望（条件性，不承诺）

视 v5 使用与信号日志积累情况再定：扩大核心池、接入组合模拟，或维持维护。
