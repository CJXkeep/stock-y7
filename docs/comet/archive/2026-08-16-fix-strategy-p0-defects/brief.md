# Outcome

修复 `docs/策略审核报告.md` 中列出的 P0 级策略缺陷（真实交易前必须处理的问题），在不改变既有权重/阈值/评分公式的前提下，消除可复现的逻辑错误与数据口径风险，并用回归测试固化修复。

# Scope

- 修复突破止损接口错配：`breakout_module.py` 输出 `signal="卖出"`，而 `signal_engine.py` 聚合器只匹配 `持仓/空头平仓/多头止损`，导致卖出信号丢失（`breakout_module.py:107-108` vs `signal_engine.py:344-351`）。
- 修复复权口径静默切换：K 线多源 fallback 从"腾讯前复权"静默切换到"新浪不复权"（`kline_fetcher.py:211-233`），长周期指标/形态可能失真。
- 定义信号可知时点：缠论信号在后续 K 线确认后回填历史分型日期，产生前视偏差（`chanlun_daily.py` 信号端点日期）。
- 修复动作与计划状态不一致：`app.py:_apply_signal_optimization` 后处理把顶层 `action` 降级（如买入→谨慎买入），但 `trade_plan.action`、摘要、风险等级、信号强度未同步（`app.py:321-340`）。
- 修复海龟加仓单位无上限：`breakout_module.py:98-105` 的 `position_units` 无上限，极端行情下仓位与止损严重失真。
- 建立最小回归测试集，覆盖上述已复现缺陷。

# Non-goals

- 不调整五模块权重（25/20/20/20/15）、不修改评分公式、不改变阈值与参数（除非修复缺陷本身要求引入明确上限）。
- 不修复 P1/P2 清单中的问题（市场宽度不重算、三角形不可达、缠论信号排序、短序列指标初值、周线参数混用、文本关键词否决、"准确率"命名等）——留待后续 change。
- 不建立历史回测框架，不计算或宣称收益率/回撤/胜率/盈利能力。
- 不提供个股买卖建议或收益承诺。
- 不修改用户界面布局与交互（若 API 输出字段语义修正，仅同步前端展示所需的最小改动）。

# Acceptance examples

- A1：突破模块"卖出"信号能进入信号聚合器并出现在 `sell_signals` / 风控链路中；合成数据可复现修复前后差异。
- A2：K 线获取返回数据源与复权口径元数据；同一策略分析全程不静默更换复权口径；合成/单元测试可验证。
- A3：缠论信号携带明确的观察/确认/可执行时点，信号不再回填到历史分型日期；文档说明时点语义。
- A4：后处理降级动作后，`trade_plan.action`、`plain_summary`、`risk_level`、`signal_strength` 与顶层 `action` 全部一致；合成数据断言字段同步。
- A5：海龟 `position_units` 有明确上限（默认 4 单位，与现有加仓价逻辑一致）；极端合成数据不再产生无上限单位。
- A6：新增最小回归测试（pytest 或等效），覆盖 A1-A5 的已复现缺陷；测试全部通过且不依赖外部网络。
- A7：修复不改变五模块权重/评分公式/既有阈值；用基线输出对比证明非缺陷路径输出不变（或说明必要的等价调整）。

# Constraints and invariants

- 项目当前无测试框架、无 Git 仓库；测试与验证全部使用纯内存合成数据，不依赖外部行情 API。
- 策略实现修改必须保持与既有"加密版反推"的可解释性；不能为了让测试通过而引入不可解释的黑盒逻辑。
- 前端 `dashboard/index.html` 只做与字段语义修正对应的最小同步改动。
- 所有修复以 `docs/策略审核报告.md` 的"已证实"缺陷为证据边界；未证实问题不纳入本 change。
