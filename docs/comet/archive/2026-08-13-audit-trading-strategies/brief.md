# Outcome

产出一份基于现有源码、文档与可复现检查的策略审核评价，明确策略逻辑、信号聚合、风险控制、数据时序、证据强度、主要缺陷及改进优先级；对无法由现有证据支持的盈利能力结论明确标注为未知。

# Scope

- 审核五模块策略：趋势、CANSLIM、突破、量价、形态。
- 审核统一信号引擎及 `app.py` 中的硬否决、软否决、信号分级、仓位与盈亏比规则。
- 审核数据口径、指标窗口、信号时序、前视偏差、样本外验证与可复现性风险。
- 纳入缠论日线与分钟买卖点模块；不开展历史绩效回测。

# Non-goals

- 本阶段不修改现有交易策略、阈值、权重或用户界面。
- 不把静态代码一致性或少量样本拟合等同于可交易盈利能力。
- 不提供个股买卖建议或收益承诺。

# Acceptance examples

- A1：报告逐一说明纳入范围内每个策略的输入、核心规则、输出、相互依赖与已发现风险。
- A2：报告审核综合评分、动作分级、否决、仓位、止损、目标价和盈亏比链路，并指出冲突规则或不可达/误判分支。
- A3：报告明确检查前视偏差、幸存者偏差、复权、交易成本、涨跌停、停牌、信号成交时点及样本外验证等关键有效性风险，区分“已证实”“高概率”“待验证”。
- A4：报告给出分维度评价、总体结论和按严重度/投入排序的改进清单，每项关联具体代码或可复现证据。
- A5：所有执行过的检查、未执行的验证及其限制均可追溯；没有证据时不声称策略具有盈利能力。

# Constraints and invariants

- 审核必须保持策略实现只读；只有审核工作流正式产物可以编辑。
- 结论以当前项目源码和实际执行结果为依据，已有《实现分析报告》只作为线索，不作为独立验证证据。
- 项目当前没有测试、回测脚本或历史样本库，这是审核证据边界的一部分。

# Decisions

- 使用中文产出审核报告。
- 审核先于任何策略修改；潜在修复仅列为建议，不在本 change 中实施。
- 采用证据分级，严格区分代码逻辑评价与历史绩效评价。
- 审核深度采用静态源码审查与定向合成数据验证，不在本 change 中建立历史回测框架；历史盈利能力保持“未知/未验证”。
- 审核范围采用全部策略：五模块、统一信号与后处理风控、缠论日线和分钟买卖点。

# Open questions

无。

# Verification expectations

- 对所有纳入范围的策略文件进行逐项源码审查，并用文件位置支撑关键结论。
- 运行不改变策略状态的语法、边界或合成数据检查；不运行历史绩效回测，并在报告中明确这一限制。
- 最终报告内部一致、风险分级明确，并逐项覆盖 A1-A5。
