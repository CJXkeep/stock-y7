# Outcome

补齐 I7.5 明确推迟的前端实用项，让核心池维护和信号档案在日常使用中真正顺手：

1. 核心池**批量导入**（粘贴多行文本一次入池，自动去重、单次版本递增）；
2. 核心池**按行业（板块）筛选**（条目新增可选 `industry` 字段，来源东财公开接口，失败留空不阻塞；面板提供行业下拉筛选与一键补全）；
3. **信号档案导出**（当前过滤结果一键导出 CSV / JSON）。

# Scope

- 后端最小配合：
  - `/api/pool` 新增 `action=import`（批量追加、逐条校验、幂等跳过、`POOL_MAX_ITEMS` 上限约束，整体成功才 `version+1` 落盘一次）；
  - `/api/pool` 新增 `action=fill-industry`（对池内 `industry` 为空的条目抓取行业，全部成功才落盘，`version+1`）；
  - `backtest/pool.py`：条目白名单增加可选 `industry`（缺省空串，旧文件读取兼容，保存不丢失）；
  - `data/kline_fetcher.py` 或同级新增单一函数：按 symbol 抓取东财行业名（标准库 urllib，带缓存，失败返回空串）；
  - app 层 add/import 单条路径顺带回填 industry（失败不阻塞加入）。
- 前端（`dashboard/index.html`，最小改动风格）：
  - 核心池面板：「批量导入」入口（多行文本域，每行 `代码` 或 `代码,名称`，兼容 Excel 复制），完成后提示 新增 X / 跳过 Y；
  - 核心池面板：行业下拉筛选（「全部」+ 池内现有行业集合）、「补全行业」按钮（调用 fill-industry 并刷新）；
  - 信号档案面板：「导出 CSV」「导出 JSON」按钮，导出**当前过滤条件下**的记录；CSV 带 UTF-8 BOM，列与面板一致；前端 Blob 本地下载，不新增后端接口。

# Non-goals

- 移动端/窄屏适配深化（维持现有单个断点）；
- 主题系统、整体布局重构、index.html 单文件拆分；
- 历史统计结果的看板展示/导出（CLI 已输出 CSV 文件，不在本迭代）;
- 自选股/历史记录等 localStorage 数据的导出；
- 任何策略、统计、日志口径变化；不新增 Python 第三方依赖。

# Acceptance examples

- A1 对 `/api/pool` 发 `{"action":"import","items":[{"symbol":"600000","name":"浦发银行"},{"symbol":"600000"},{"symbol":"000001","name":"平安银行"}]}`：600000 只计入一条（幂等跳过），响应含 `{ok:true, added:2, skipped:1}`，`version` 恰好 +1，items 顺序稳定且落盘一次。
- A2 import 触发上限约束：池已有 59 条时导入 5 只 → 仅收满至 60 条，响应如实报告 added/skipped（含因超限未加入的数量），`ok:true`；池满时导入全部被拒并给出明确 error 文案。
- A3 非法输入防御：import 缺 items、items 含空 symbol/非 6 位数字 symbol 时逐条校验，非法条目计入 skipped 且不影响合法条目；完全非法返回 `{ok:false,error:...}` 且不落盘、version 不变。
- A4 `action=add` 与 import 成功路径会尝试回填 `industry`；行业抓取抛错/超时时条目仍正常入池，`industry` 为空串，响应不含错误。
- A5 `action=fill-industry`：对池内 industry 为空的条目逐一抓取；至少一只成功填充则落盘且 `version+1`；全部失败返回 `{ok:false,error:...}` 且不落盘；无缺失时返回 ok 且不写盘。
- A6 兼容性：对不含 `industry` 的旧版 `data/pool.json` 执行 load→save 往返后，原有字段值不变且新增条目带 `industry` 键；损坏文件回退空池行为不变。
- A7 核心池面板存在「批量导入」交互：多行文本（每行 `代码` 或 `代码,名称`）提交后列表刷新并显示 新增/跳过 计数；存在行业下拉（含「全部」）选择后仅显示对应条目；存在「补全行业」按钮且点击后刷新。
- A8 信号档案面板存在「导出 CSV」「导出 JSON」按钮：导出内容等于当前过滤参数（type/symbol/include_dupes）下的 records；CSV 以 UTF-8 BOM 开头且首行为表头，JSON 为对象数组；两者均通过浏览器本地下载完成，网络层无新增请求。
- A9 `run_all_tests.py` 全量通过，既有测试零回归；新增行为有对应单元测试（pool import/fill-industry/兼容往返；fetcher 行业解析离线用例）。

# Constraints and invariants

- 仅标准库；沿用既有缓存/UA/超时风格；
- `pool.json` 仍为唯一事实来源：有序、symbol 唯一、成功变更 `version` 严格 +1、原子写盘；幂等拒绝与整体失败不写盘；
- 新字段必须向后兼容（缺省可读、白名单保留）；
- 行业数据为辅助信息：获取失败一律降级为空串，绝不阻塞主流程；
- 前端延续「最小同步改动」，不重构布局；导出在前端生成，不新增后端导出接口；
- 不改变策略/统计/日志语义。

# Decisions

- 2026-08-22 范围方向：结构化提问被用户中断并指示「继续」，按提问时给出的推荐默认执行——本轮只做 **A：补齐 I7.5 推迟项**（批量导入 / 按板块筛选 / 信号档案导出）；B 信息密度打磨、C 移动端适配、D 工程拆分列为非目标，留待后续迭代。（用户可在最终确认时推翻）
- 2026-08-22 后端边界：允许最小后端配合（推荐默认）：行业数据与批量导入需要 API 支持，延续历次迭代「前后端最小同步」风格。
- 2026-08-22 「按板块筛选」落地口径：仓库现无任何行业数据源，采用东财公开接口按 symbol 抓取行业名，作为可选 `industry` 字段存入池条目；不引入手动标签体系，也不做整市场行业表下载。理由：与既有东财数据源同族、增量成本最低、筛选语义真实。
- 2026-08-22 导出实现位置：纯前端 Blob 下载（当前过滤结果），不新增后端导出 API；CSV 用 UTF-8 BOM 保证 Excel 中文兼容。
