# Outcome

在趋势分析工具里新增**模拟账户**（paper trading）：一个用虚拟资金、按现有信号策略
**自己选股并自动执行买卖**的记账系统，同时给出账户概览与组合级绩效指标
（年化 / 最大回撤 / 夏普 / 卡玛）。

它落地的是 `docs/评估模块设计.md` §5.5「组合级模拟」这个条件项：评估模块回答
「信号质量如何」（只测量不优化），本能力回答「按策略实际执行出来的账户结果长什么样」。

全链路为：**选股 → 决策 → 执行 → 持仓管理 → 记账 → 绩效**，像交易员一样主动在全市场
找机会，而不是盯一份固定清单。

# Scope

## 0. 架构约束：与策略解耦（核心）

qushi 趋势策略后续仍会演进甚至被替换，因此模拟账户**不与具体策略耦合**：
账户、撮合、记账、绩效属于稳定的「交易所 + 账户」模型，策略只是可插拔的决策来源。

- 账户层只认标准化决策 `Decision`（side / level / score / stop / target / trigger_date /
  strategy），**不 import 信号引擎**，不出现「强烈买入 / 谨慎买入」等策略专有文案；
- 当前策略经 `QushiV5Adapter` 接入（action → Decision 的映射表是全局唯一一处策略专有逻辑），
  后续换策略只需新增适配器，账户层与前端零改动；
- 标的来源同样可插拔（`UniverseProvider`：全 A 扫描 / 自选 / 核心池）；
- 流水与持仓记录 `strategy` 字段，支持未来多策略并行与归因；
- 附带收益：账户层可注入假 `Decision` 做**全离线**测试，策略演进不影响账户回归。

## 1. 选股（策略自己选股，不依赖固定列表）

- 默认 `universe=scan`：全 A 股快照排除 ST / 退市 / 停牌（价格≤0），按成交额取前 N
  （默认 300 只）作为选股池；
- 日 K 分析走本地 kline store + 全 A 快照行当行情 / 当日 bar，**零逐股行情请求**
  （复用 `scan_engine` 快路径：`quote_from_row` + `synthesize_bar_from_row` +
  `fetch_kline(bridge=False)`）；
- 命中买入档位的候选**补拉资金流重算**，最终动作与看板 `/api/analyze` 口径一致
  （`run_analysis` + `_apply_signal_optimization`）；
- 备选项：`watchlist`（自选股）、`pool`（核心池），配置可切换；
- 节流：选股比持仓巡检贵，按 `screening_interval_min`（默认 60 分钟）节流；
  持仓数已达上限时直接跳过选股。

## 2. 决策（排序与过滤）

- 排序：综合分（`score`）降序，置信度次之；
- 不买入的情形：已持有该标的、同一 `trigger_date` 已买过、当日卖出过该标的、
  评分低于 `min_score`、持仓数达 `max_positions`、可用资金不足一手；
- 仓位：单笔基准金额 = 总资产 × `per_trade_pct`（默认 20%）× 档位系数
  （强烈买入 1.0 / 买入 0.7 / 谨慎买入 0.4），且「货款 + 买入费用 ≤ 可用资金」，
  否则降一手重试，仍不足则跳过本笔。

## 3. 执行（撮合口径，与 `stats.simulate_signal` 同源）

- 成交价 = 行情价 ± 滑点 `SLIPPAGE_RATE` 0.1%（买入上浮 / 卖出下压），0.01 元步进；
- 费用 = 佣金 `max(0.025% × 金额, 5 元)` 双边 + 印花税（卖出单边 0.05%）；
- 整手 `LOT_SIZE` 100 股；可用资金买不起一手不下单；
- A 股 **T+1**：当日买入的持仓当日不可卖出；
- **单标的单仓位**：已持有同标的不再加仓（避免 T+1 分笔歧义），卖出支持全部 / 部分。

## 4. 持仓管理（卖出）

触发原因与判定顺序：**超期 → 止损 → 止盈 → 信号**（止损优先于止盈，同日双触保守记止损）：

| 原因 | 触发条件 |
|---|---|
| `max_hold` | 持有交易日 ≥ `max_hold_days`（0 = 不限） |
| `stop` | 现价 ≤ 持仓记录的止损价（建仓时来自 `Decision.stop`） |
| `target` | 现价 ≥ 持仓记录的目标价（建仓时来自 `Decision.target`） |
| `signal` | 引擎最终动作 ∈ {卖出, 强烈卖出} |
| `manual` | 用户在看板手动卖出 |

持仓巡检每轮都执行（标的数量少），需要重新分析该股以取得最新动作。

## 5. 记账（事实来源 `data/sim/`）

| 文件 | 内容 | 写入方式 |
|---|---|---|
| `config.json` | 策略与风控配置 | 原子写，version 递增 |
| `state.json` | 现金 / 持仓 / 统计 | 原子写 |
| `trades.jsonl` | 成交流水 | append-only |
| `equity.jsonl` | 净值快照（每巡检周期一行） | append-only |

- 成本口径：持仓 `cost_basis` **含买入费用**；卖出盈亏 = 卖出净收入 − 按比例结转的成本；
- 净值 = 可用资金 + 持仓市值（持仓按现价估值）。

## 6. 绩效

- **账户概览**：总资产、可用资金、持仓市值、总盈亏与收益率、已实现盈亏、浮动盈亏、
  胜率、交易笔数；
- **组合级指标**（在 `equity.jsonl` 净值序列上计算）：年化收益率、最大回撤、夏普、
  卡玛——即评估模块 §5.5 中「需组合净值才有资格谈」的那批指标；
- 净值曲线在前端用 ECharts 渲染。

## 7. 调度与运维

- 交易时段内按 `interval_min`（默认 15 分钟）巡检；持仓巡检每轮都做，选股按节流；
- **默认关闭**（`enabled=false`），需手动开启，与钉钉推送 watcher 一致；
- 单进程约束（与 scan / digest / notify 一致，gunicorn 必须 `--workers 1`）；
- 任务状态经 `server/task_store.py`（kind=sim）落盘，重启可回填；
- 支持「立即执行一轮」（`force` 可跳过交易时段限制）用于验证。

## 8. 接口与前端

- `GET /api/sim`：配置 + 账户 + 持仓 + 成交流水 + 净值序列 + 运行状态；
- `POST /api/sim`：`save`（配置）/ `run_once`（立即执行一轮）/ `reset`（重置账户）/
  `buy` / `sell`（手动买卖）；
- 看板新增侧边栏**「模拟」分区**：账户概览、持仓列表（含止损/目标/盈亏）、
  成交流水、净值曲线、配置面板（开关 / 资金 / 选股范围 / 档位 / 仓位 / 巡检间隔）；
- 回归测试 + README / 版本路线图 / CLAUDE.md 同步 + 沉淀 `docs/` 总设计文档。

# Non-goals

- **不接真实券商 / 实盘下单**：策略触发与手动触发的买卖全部是记账层面的模拟成交；
- 不改动信号引擎与后处理逻辑（买入判定沿用既有的「最终 action」）；
- 不做自动调参、不按模拟结果回头选参数（沿用「评估只测量不优化」）；
- **模拟成交不写入信号档案 `data/journal/`**：避免污染真实信号档案，账户自带
  `trades.jsonl` 作为流水事实来源；
- 不做分钟级 / 日内撮合与 T+0；
- 不做净值曲线之外的归因分析（行业暴露、风格暴露等）；
- 不改核心池 / 候选池语义，模拟账户不反向写 `pool.json` / `candidates.json`。

# Acceptance examples

- **A1** 选股：`universe=scan` 时全 A 快照剔除 ST / 退市 / 停牌后按成交额取前 N；
  命中买入档位的候选补拉资金流重算，其最终动作与 `/api/analyze` 同标的同口径一致。
- **A2** 决策：候选按综合分降序；已持有、同 `trigger_date` 已买、当日卖出过、
  评分低于 `min_score`、持仓数达上限、现金不足一手的候选均不买入。
- **A3** 仓位：强烈买入 / 买入 / 谨慎买入三档的实际买入金额 ≈
  总资产 × `per_trade_pct` × 档位系数（1.0 / 0.7 / 0.4），且货款 + 费用不超过可用资金。
- **A4** 撮合：成交价 = 行情价 ± 0.1% 滑点（买上浮 / 卖下压，0.01 元步进）；
  费用 = 佣金 `max(0.025% × 金额, 5 元)` 双边 + 印花税卖出 0.05%；按 100 股整手下单。
- **A5** T+1 与单仓位：当日买入的持仓当日不可卖出；单标的单仓位，已持有不再买入。
- **A6** 卖出：超期 / 止损 / 止盈 / 信号 / 手动五类原因均可触发卖出，
  判定顺序为 超期 → 止损 → 止盈 → 信号。
- **A7** 记账：`cost_basis` 含买入费用；卖出盈亏 = 卖出净收入 − 结转成本（净盈亏已扣
  全部费用）；`trades.jsonl` 逐笔可手工核对，资金守恒
  （现金 + 持仓市值 = 初始资金 + 累计净盈亏）。
- **A8** 绩效：净值序列上可算出年化 / 最大回撤 / 夏普 / 卡玛，数值可手算复核，
  样本不足时明确标注而非硬算。
- **A9** 调度：默认关闭；开启后仅在交易时段按 `interval_min` 巡检；选股受
  `screening_interval_min` 节流；持仓数达上限时跳过选股。
- **A10** 持久化：配置 / 状态 / 流水 / 净值均落 `data/sim/`，服务重启后账户状态完整恢复。
- **A11** 接口：`GET /api/sim` 返回配置 + 账户 + 持仓 + 流水 + 净值 + 状态；
  `POST /api/sim` 支持 save / run_once / reset / buy / sell，非法输入返回明确错误而非 500。
- **A12** 前端：看板「模拟」分区可看概览 / 持仓 / 流水 / 净值曲线，
  可开关自动交易、可手动买卖，行情延迟与「非投资建议」有披露。
- **A13** 回归：新增测试覆盖撮合费滑点、T+1、止损止盈判定、仓位计算、持久化恢复、
  重启回填；`python run_all_tests.py` 全绿。
- **A14** 文档：README / 版本路线图 / CLAUDE.md 同步，并沉淀一份 `docs/` 总设计文档。
- **A15** 涨跌停顺延：买入触及涨停价不成交并顺延，顺延超过 5 次记 `unfilled`；
  卖出触及跌停价顺延，达 5 次按当时价强制成交并标 `forced`；
  涨跌幅阈值函数与 `stats.simulate_signal` 同源（区分主板 / 创业板 / 科创板 / ST）。
- **A16** 策略解耦：`backtest/sim_account.py` 不 import 信号引擎；注入假 `Decision`
  即可完整跑通「买入 → 持仓 → 卖出 → 记账 → 绩效」全链路；`QushiV5Adapter` 的
  action → Decision 映射有独立测试；替换适配器不影响账户层测试。

# Constraints and invariants

- **单进程部署**：进行中的巡检状态在进程内存，必须 `python app.py` 单进程运行
  （gunicorn 必须 `--workers 1`，Docker 多副本不可用）。
- **口径不可混用**：买入判定用「最终 action」（含后处理），与信号档案 / 看板一致；
  不与历史统计的「原始 `run_analysis` 输出」混用。
- **成交口径同源**：滑点 / 费率 / 整手与 `stats.simulate_signal` 保持一致，只是扩展为
  组合记账（并发持仓 + 资金占用）。
- **账户独立**：模拟账户独立记账，不写 `data/journal/` 信号档案，不反向改池。
- **分层**：不联网的纯记账（`backtest/sim_account.py`）与联网的策略执行层
  （`server/sim_strategy.py` 适配器 + `server/sim_service.py` 编排 / 巡检 / 调度 / API）分离。
- **账户与策略解耦**：账户层不 import 信号引擎，只依赖 `Decision` 契约；
  策略专有逻辑集中在 `server/sim_strategy.py` 的适配器内（详见 Spec §1.1 / §2）。
  策略演进只改策略层，账户层与前端不受影响。
- 涨跌停 / 停牌等撮合边界按 Decisions 处理，并在流水备注中披露。
- 免费行情源有延迟，模拟成交价 ≠ 实盘成交价；**自用参考，非投资建议**。
- 全部依赖 Python 标准库，不引入第三方运行时依赖。

# Decisions

- **D1 选股方式**：策略自己全市场选股（`universe=scan`，默认成交额前 300 只），
  不是只盯自选列表；`watchlist` / `pool` 作为配置可切换的备选。
- **D2 买入档位**：三档全买（强烈买入 / 买入 / 谨慎买入），谨慎买入按轻仓（系数 0.4）。
- **D3 卖出规则**：信号 + 止损 + 止盈自动卖出，另支持手动操作。
- **D4 手动交易**：手动买入 + 手动卖出都支持，且全部为记账层面的模拟成交，
  不触碰任何真实券商账户。
- **D5 绩效深度**：账户概览 + 组合级指标（年化 / 最大回撤 / 夏普 / 卡玛）——
  评估模块 §5.5 的条件项正好被组合净值序列解锁。
- **D6 文档双轨**：先走 Comet 出 spec，实现后再沉淀一份 `docs/` 总设计文档（I9 同款）。
- **D7 工作区**：CLI 的 branch 隔离要求干净工作区，而本会话中清理审批不可用、
  worktree 触发环境超时，实际以 `current` 隔离创建 change；这不改变任何产出内容，
  归档收尾方式留到 Archive 阶段再定。
- **D8 无风险利率**：夏普的无风险利率默认取 0% 并在结果处披露口径
  （个人工具简化，不引入外部利率数据源）。
- **D9 默认关闭**：自动交易默认 `enabled=false`，需手动开启，与钉钉推送 watcher 一致，
  避免服务启动即静默下单。
- **D10 初始资金**：默认 10 万元，与 `config.CAPITAL_DEFAULT` 对齐（个人资金规模，
  无市场冲击问题）。
- **D11 涨跌停撮合**：对齐 `stats.simulate_signal` 的顺延口径（涨停顺延 5 次→`unfilled`；
  跌停顺延 5 次→强制成交标 `forced`），而非「保守跳过」或「不做判断」。
  理由是设计稿 §5.5 明确要求成交口径复用 `simulate_signal`，对齐后账户结果可与历史统计比较；
  代价是持仓需跟踪顺延计数，已在数据模型中预留。
- **D12 双周期选股**：候选先取日 K 动作，再跑周 K 验证（周 K 由本地日 K 聚合，不额外联网），
  仅保留周 K 同属买入档位的标的，与看板「扫描买入」口径一致；
  由配置 `require_weekly`（默认 `true`）控制，关闭后只按日 K 决策（更快、更激进）。
- **D13 手动交易约束**：手动买入不做信号校验（用户自主决策），但仍受资金、整手、
  涨停顺延、单标的单仓位、持仓上限约束；手动卖出不可绕过 T+1 与跌停顺延；
  `reset` 不可逆，前端须二次确认，重置前的平仓以 `reason=reset` 留在流水中。
- **D14 年化口径**：年化公式中的 N 取净值序列**按日期去重后**的交易日数
  （每巡检周期都会写一行快照，同一天多行只计一个交易日）。
- **D15 架构解耦**：账户 / 撮合 / 记账 / 绩效与策略解耦，两者只通过 `Decision` 契约通信；
  策略以 `StrategyAdapter` 可插拔接入（当前 `QushiV5Adapter`），标的来源以
  `UniverseProvider` 可插拔接入。理由是 qushi 策略后续会演进，账户不应被绑死；
  仓位系数改按 `Decision.level`（strong / normal / cautious）配置，不再绑定策略档位名。
