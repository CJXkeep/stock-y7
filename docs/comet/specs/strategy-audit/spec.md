# 策略审核能力规格

## 目标

系统应提供一份中文策略审核报告，以当前项目源码、文档和可复现的只读检查为证据，评价交易策略的逻辑完整性、数据与时序正确性、风险控制、可验证性及实际使用风险。审核结论不得超出证据边界。

## 审核范围

审核必须覆盖：

1. 趋势、CANSLIM、突破、量价、形态五个评分模块；
2. `signal_engine.py` 的模块聚合、动作、置信度、风险等级与交易计划；
3. `app.py` 的市场宽度修正、硬否决、软否决、信号分级、仓位和盈亏比规则；
4. 缠论日线的包含处理、分型、笔、中枢、背驰及一二三类买卖点；
5. 缠论分钟级 K 线构造、分型、笔、背驰及买卖点；
6. K 线、行情、资金流、指数和市场宽度数据在策略链路中的口径与时序。

## 审核方法

审核必须：

- 以源码为主要证据，既有实现分析报告仅作为调查线索；
- 对关键权重、阈值、分支、时间窗口和数据依赖进行静态追踪；
- 使用不改变策略状态的语法检查、边界检查或合成数据检查验证重要判断；
- 检查前视偏差、幸存者偏差、复权、停牌、涨跌停、交易成本、成交时点、样本外验证和数据缺失处理；
- 将结论标记为“已证实”“高概率”或“待验证”，并说明证据来源和限制；
- 区分代码是否按设计执行、设计是否合理，以及策略是否具有历史盈利能力。

## 报告要求

报告必须：

- 逐项说明每个纳入策略的输入、核心规则、输出、相互依赖、优点和风险；
- 说明从原始数据到最终操作建议的完整决策链，并指出冲突规则、重复计分、不可达分支或误判风险；
- 给出数据质量、策略逻辑、风险控制、工程可靠性、可解释性和证据成熟度的分维度评价；
- 给出总体结论，并明确适用边界及是否适合直接用于真实交易；
- 提供按严重度和投入排序的改进清单，每项关联具体代码位置或可复现证据；
- 列出实际运行的检查、没有运行的验证及原因。

## 验收标准

- A1：报告逐一说明纳入范围内每个策略的输入、核心规则、输出、相互依赖与已发现风险。
- A2：报告审核综合评分、动作分级、否决、仓位、止损、目标价和盈亏比链路，并指出冲突规则或不可达/误判分支。
- A3：报告明确检查前视偏差、幸存者偏差、复权、交易成本、涨跌停、停牌、信号成交时点及样本外验证等关键有效性风险，区分“已证实”“高概率”“待验证”。
- A4：报告给出分维度评价、总体结论和按严重度/投入排序的改进清单，每项关联具体代码或可复现证据。
- A5：所有执行过的检查、未执行的验证及其限制均可追溯；没有证据时不声称策略具有盈利能力。

## 非目标与约束

- 不修改策略实现、权重、阈值、数据接口或用户界面；
- 不建立历史回测框架，不计算或宣称收益率、最大回撤、胜率或实盘盈利能力；
- 不提供个股买卖建议或收益承诺；
- 除 Comet 正式审核产物外，项目实现保持只读。
