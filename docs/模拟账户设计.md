# 模拟账户（组合模拟）设计

> v6 落地，2026-09-01。Comet change：`sim-account`（归档见 `docs/comet/archive/`）。
> 本文是「先 Comet 出 spec、实现后沉淀 docs 总设计」双轨产物中的总设计文档。

## 1. 定位与边界

模拟账户是一个用**虚拟资金**、按现有信号策略**自己选股并自动执行买卖**的记账系统，
同时给出账户概览与组合级绩效（年化 / 最大回撤 / 夏普 / 卡玛）。

它落地的是 `docs/评估模块设计.md` §5.5「组合级模拟」这个条件项：

| 模块 | 回答的问题 | 只测量 | 产物 |
|---|---|---|---|
| 评估模块 | 信号质量如何（信号后价格往哪走） | 是 | 胜率 / 超额 / 单调性 |
| 模拟账户 | 按策略实际执行出来的账户结果长什么样 | 是 | 净值曲线 / 年化 / 回撤 / 夏普 / 卡玛 |

两者共享同一套信号，但产物与用途互不替代；评估是"测刀"，模拟账户是"记账"。

**明确不做**（Non-goals）：不接真实券商（策略触发与手动买卖全部是记账层面的模拟成交）；
不改动信号引擎；不按模拟结果自动调参；模拟成交不写 `data/journal/` 信号档案；
不做分钟级 / 日内撮合与 T+0；不做净值曲线之外的归因分析；不改核心池 / 候选池。

## 2. 与策略解耦（核心架构约束）

qushi 趋势策略（`analysis/signal_engine.py` 五模块 + 后处理）后续仍会演进甚至被替换，
因此模拟账户**不与任何具体策略耦合**：账户、撮合、记账、绩效属于稳定的
「交易所 + 账户」模型，策略只是**可插拔的决策来源**。

```text
┌─ 策略层（可插拔，后续可换）─────────────────────────────┐
│  UniverseProvider   标的从哪来（scan / watchlist / pool）  │
│  StrategyAdapter    策略怎么判断 → Decision                │
│     └─ QushiV5Adapter（当前唯一实现）                      │
└─────────────────────────────────────────────────────────┘
                      ↓  Decision（唯一契约）
┌─ 账户层（与策略无关，稳定）───────────────────────────┐
│  SimBroker    撮合：滑点 / 费率 / 涨跌停 / T+1 / 整手      │
│  Account      记账：现金 / 持仓 / 流水 / 净值              │
│  Performance  绩效：年化 / 回撤 / 夏普 / 卡玛              │
└───────────────────────────────────────────────────────┘
```

**`Decision` 契约**（`backtest/sim_account.py`）只描述「想做什么、以什么价位防守」：

```text
symbol / name / side(buy|sell|hold) / level(strong|normal|cautious)
score / confidence / price / pre_close / stop / target
trigger_date / strategy / reason
```

不含 `module_scores`、`momentum`、`risk_codes` 等任何策略专有字段。
`QushiV5Adapter` 的 action→Decision 映射表（强烈买入→buy/strong、买入→buy/normal、
谨慎买入→buy/cautious、卖出→sell、观望→hold）是**全局唯一一处策略专有逻辑**，
换策略只需新增适配器，账户层与前端零改动。

## 3. 全链路

**选股 → 决策 → 执行 → 持仓管理 → 记账 → 绩效**

### 3.1 选股（universe）

- `scan`（默认）：全 A 快照剔除 ST / 退市 / 停牌（价格 ≤ 0）→ 按成交额降序取前
  `scan_limit`（默认 300）；
- `watchlist`（自选股）/ `pool`（核心池）为可切换备选；
- 日 K 走本地 K 线库 + 快照行当行情 / 当日 bar（`quote_from_row` +
  `synthesize_bar_from_row` + `fetch_kline(bridge=False)`），除候选补拉资金流外
  **零逐股行情请求**；
- 两阶段：无资金流初筛 → 命中买入档位补拉资金流重算（与 `/api/analyze` 同口径）；
- 双周期：候选再做**周 K 二次验证**（周 K 由本地日 K 聚合），仅保留周 K 同属买入档位
  的标的（与看板「扫描买入」口径一致）；`require_weekly` 可关闭。

### 3.2 决策

候选按综合分降序（置信度次之）。不买入的情形：

1. 已持有该标的（单标的单仓位）；
2. `recent[symbol]` 中同一 `trigger_date` 已买过；
3. 当日已卖出过该标的；
4. 综合分 < `min_score`；
5. 持仓数 ≥ `max_positions`；
6. 可用资金不足一手（含费用）。

仓位：`budget = 总资产 × per_trade_pct(20%) × level_scale[level]`
（strong 1.0 / normal 0.7 / cautious 0.4），再与可用资金取小；
可买手数按「货款 + 买入费用 ≤ 资金」逐手下调，不足一手则跳过。

### 3.3 执行（撮合）

成交口径与 `stats.simulate_signal` **同源**：

- 成交价 = 行情价 ± 滑点 0.1%（买上浮 / 卖下压，0.01 元步进）；
- 费用 = 佣金 `max(0.025% × 金额, 5 元)` 双边 + 印花税（卖出单边 0.05%）；
- 整手 100 股；T+1：当日买入不可卖；单标的单仓位；
- 建仓时把 `Decision.stop / target` 写入持仓作为自动卖出依据。

### 3.4 持仓管理（卖出）

每轮巡检执行，判定顺序固定为 **超期 → 止损 → 止盈 → 信号**：

| 顺序 | 原因 | 条件 | 开关 |
|---|---|---|---|
| 1 | `max_hold` | 持有交易日 ≥ `max_hold_days` | `max_hold_days > 0` |
| 2 | `stop` | 现价 ≤ 持仓止损价 | `stop_loss_enabled` |
| 3 | `target` | 现价 ≥ 持仓目标价 | `take_profit_enabled` |
| 4 | `signal` | 当期 `Decision.side == "sell"` | `auto_sell` |
| — | `manual` | 用户手动卖出 | 始终可用 |

止损优先于止盈（同日双触保守记止损）。

### 3.5 记账

事实来源 `data/sim/`：

| 文件 | 内容 | 写入 |
|---|---|---|
| `config.json` | 策略与风控配置 | 原子写，version 递增 |
| `state.json` | 现金 / 持仓 / 统计 / 去重标记 | 原子写 |
| `trades.jsonl` | 成交流水 | append-only |
| `equity.jsonl` | 净值快照（每周期一行） | append-only |

成本口径：持仓 `cost_basis` **含买入费用**；卖出盈亏 = 卖出净收入 − 按比例结转的成本；
净值 = 可用资金 + 持仓市值（持仓按现价估值）。资金守恒：
`现金 + 持仓市值 = 初始资金 + 累计净盈亏`（盈亏已扣全部费用）。

### 3.6 绩效

在净值序列（按日期去重）上计算：总收益率、年化收益率
`(末值/初值)^(252/N) − 1`（N = 去重后交易日数）、最大回撤、夏普
（无风险利率 **0%** 并披露）、卡玛、胜率。净值样本 < 20 点时四项组合指标
**照常展示但标注「样本不足」**，不下结论（沿用 `SAMPLE_MIN` 披露纪律）。

## 4. 涨跌停与边界

**涨跌幅阈值**按代码前缀 / ST 标记判定（主板 10% / ST 5% / 创业板科创板 20% /
北交所 30%），与回测同源：

```text
limit_up(prev_close)   = prev_close × (1 + 阈值/100 × 0.995)
limit_down(prev_close) = prev_close × (1 − 阈值/100 × 0.995)
```

| 场景 | 处理 |
|---|---|
| 买入触及涨停 | 不成交并顺延；顺延 > `EXIT_POSTPONE_LIMIT`(5) 记 `unfilled` 放弃 |
| 卖出触及跌停 | 不成交，持仓 `exit_postpone` +1 顺延；达 5 次按当时价强制成交标 `forced` |
| 停牌 / 无报价 | 该标的不参与选股、不触发买卖；持仓按成本价兜底估值 |
| 行情源失败 | 该股跳过本轮，其余继续，不中断巡检 |
| 非交易时段 | 不自动巡检；`run_once force=true` 可强制执行 |
| 配置 / 状态文件损坏 | 回退默认值并告警，服务照常启动 |

## 5. 调度与运维

- 默认关闭（`enabled=false`），与钉钉推送 watcher 一致，避免服务启动即静默下单；
- 交易时段内按 `interval_min`（默认 15 分钟）巡检；持仓巡检每轮都做，
  选股受 `screening_interval_min`（默认 60 分钟）节流；
- 单轮互斥（并发触发返回 busy）；单进程部署约束不变（gunicorn `--workers 1`）；
- 任务状态经 `server/task_store.py`（kind=sim）落盘，重启回填。

## 6. 接口与前端

### `GET /api/sim`

```text
{ ok, config, account, positions[], trades[], equity[], metrics, state }
```

- `account`：现金 / 净值 / 持仓市值 / 总盈亏与收益率 / 已实现 / 浮动 / 胜率 / 笔数；
- `metrics`：annualized / max_drawdown / sharpe / calmar / sample_sufficient / days；
- 行情获取失败不 500：个股降级为成本价估值，其余照常返回。

### `POST /api/sim`

| action | 入参 | 行为 |
|---|---|---|
| `save` | 配置字段子集 | 归一化后原子保存，version 递增 |
| `run_once` | `force`（可选） | 后台执行一轮巡检 |
| `reset` | `capital`（可选） | 清仓并按新初始资金重置（不可逆，前端二次确认） |
| `buy` | `symbol`、`amount`（可选） | 手动买入（不做信号校验，仍受资金 / 整手 / 涨停 / 单仓位约束） |
| `sell` | `symbol`、`shares`（可选） | 手动卖出（受 T+1 与跌停顺延约束） |

非法入参返回 `{"ok": false, "error": "<原因>"}`，不抛异常、不 500。

### 前端

看板侧边栏新增「**模拟**」分区：账户概览、组合指标卡（样本不足标注）、净值曲线
（ECharts，含初始资金基准线）、持仓列表（含止损 / 目标 / 浮动盈亏 / 卖出按钮）、
成交流水、配置面板（开关 / 资金 / 选股范围 / 档位 / 仓位 / 巡检间隔 / 止损止盈）。

披露：行情源有延迟、模拟成交价 ≠ 实盘成交价、**自用参考非投资建议**。

## 7. 验收与测试

验收项 A1–A16（见 Comet brief）覆盖：选股口径、决策过滤、仓位档位、撮合费滑点、
T+1 / 单仓位、五类卖出、成本结转与资金守恒、绩效手算、调度节流、持久化重启、
接口契约、前端分区、全量回归、文档同步、涨跌停顺延、策略解耦。

测试：`tests/test_sim_account.py`（账户内核，注入假 Decision 全离线）、
`tests/test_sim_strategy.py`（映射表与周 K 验证）；`python run_all_tests.py` 全绿。

## 8. 展望

本次 v1 只挂载 `qushi_v5` 单策略；架构已预留 `strategy` 字段、`StrategyAdapter` 与
`UniverseProvider` 接口，未来支持多策略并行与归因时无需改动账户层与前端。
剩余条件项：扩大核心池、净值归因分析（行业 / 风格暴露），或维持维护。
