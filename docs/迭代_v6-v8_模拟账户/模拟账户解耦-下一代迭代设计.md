# 模拟账户下一代迭代：配置与策略解耦 + 选股错峰

> 日期：2026-09-01。定位：下一代迭代设计稿（本轮不实施）。
> 背景：v6 模拟账户上线后试用反馈——配置面板与 qushi 策略概念强绑定；定时巡检与行情源限流的叠加风险需要显式治理。

## 1. 问题定义

### 1.1 配置面与策略强绑定（主问题）

v6 架构层已按「账户层不认识策略」解耦（`Decision` 契约 + `StrategyAdapter` 插拔），
但**配置面**遗留了策略专属概念，写死在通用配置 schema（`v6.sim.config.v1`）里：

| 字段 | 问题 |
|---|---|
| `buy_levels`（strong/normal/cautious） | qushi 信号档位名，换策略后语义失效 |
| `level_scale`（1.0/0.7/0.4） | 档位→仓位比例映射，同样依赖 qushi 档位 |
| `min_score` | 「综合分」是 qushi 五模块的概念 |
| 前端配置面板 | 把上述字段当作账户参数固定展示 |

后果：换策略时这些配置变成无意义死字段；新 adapter 无法声明自己需要的参数。

### 1.2 选股巡检与行情源限流（次问题，本次试用已实测）

巡检本身成本极低（初筛走本地 K 线库，零逐股网络请求），但与 K 线同步
catchup（启动时 2000 只）、滚动评估等共享同一免费行情源时会被 WAF 限流
（2026-09-01 实测：巡检选股阶段大面积 `腾讯K线被WAF拦截`，初筛空手而归）。

## 2. 方案

### 2.1 配置拆两层

```text
v7.sim.config.v1
├─ 账户/引擎参数（与策略无关，永远有效）
│   enabled / initial_capital / universe / scan_limit
│   interval_min / screening_interval_min / max_positions
│   stop_loss_enabled / take_profit_enabled / max_hold_days / auto_sell
└─ strategy_params（字典，由 adapter 自描述）
    qushi_v5: { buy_levels, level_scale, min_score, require_weekly }
```

- `strategy_params` 对后端是不透明字典，由当前 adapter 声明 schema 并做归一化校验；
- 兼容迁移：读到 v1 配置时，把策略专属字段搬进 `strategy_params`，version 递增一次。

### 2.2 adapter 自描述参数 schema

```python
class StrategyAdapter:
    id = "base"
    def params_schema(self) -> dict:
        """声明本策略的可配置参数：{key: {type, default, min, max, options, label}}。"""
        raise NotImplementedError
    def normalize_params(self, raw: dict) -> dict:
        """按 schema 归一化外部输入；非法值回退默认。"""
```

- `QushiV5Adapter` 迁移：`build_context` / `screen` 改为从 `strategy_params` 读参；
- `GET /api/sim` 返回 `strategy_schema`（由当前 strategy 的 `params_schema()` 生成），
  非法 `strategy` 值回退默认 adapter 并在 state 中告警。

### 2.3 前端动态渲染

- 配置面板拆「账户参数」（固定字段）与「策略参数」（由 `strategy_schema` 驱动动态生成）两区；
- 换策略时策略参数区自动跟随，不再需要前端发版；
- 大页（`sim.html`）与侧边栏窄栏共用同一渲染逻辑。

### 2.4 选股错峰（限流治理）

- 选股调度避开整点后 K 线同步窗口（如 `KLINE_SYNC_AT` 后 10 分钟内不启动选股）；
- 资金流补拉加全局限速（复用 kline_fetcher 的节流基础设施，若有）；
- 连续 N 只候选被 WAF 拦截时提前终止本轮选股并在 state 标记 `source_throttled`，
  避免空耗配额。

## 3. 明确不做

- 不做多策略并行账户（架构已预留，但本轮仍单策略单账户）；
- 不改账户层撮合 / 记账 / 绩效逻辑（已验证稳定）；
- 不做参数自动寻优（沿用第一性原则：参数调整必须由足够样本支持）。

## 4. 验收标准

1. `normalize_config` 对 v7 配置的部分保存只更新提供字段，账户参数与 strategy_params 互不污染；
2. v1 旧配置文件首次读取自动迁移，字段无丢失；
3. 换一个假 adapter（声明不同 schema）时，`/api/sim` 返回其 schema，前端策略参数区正确渲染；
4. 全量回归 `python run_all_tests.py` 全绿；
5. 错峰逻辑：模拟 K 线同步窗口内触发的选股被推迟，state 可见推迟原因。

## 5. 工作量预估

| 部分 | 预估 |
|---|---|
| 后端：schema 拆分 + 迁移 + adapter params_schema | 约 0.5 天 |
| 前端：策略参数区动态渲染（大页 + 窄栏） | 约 2–3 小时 |
| 错峰与限速治理 | 约 2 小时 |
| 测试与文档 | 约 2 小时 |
