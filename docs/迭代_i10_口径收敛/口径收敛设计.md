# I10 迭代设计：口径收敛——最终动作纳入重放（policy 版本化）

> 排定：2026-09-02。状态：设计稿（先设计、后实现）。
> 本源对齐（沿用）：**自己先用 · 核心价值=实用 · 接受"未经实证"但绝不自欺**。
> 直接依据：`docs/策略迭代-第一性原则-v1.md` §2 末行「回测与实时后处理存在口径差异 → 待下一轮」；`docs/版本路线图.md` 剩余展望 #1。
> 代码事实核对日期：2026-09-02（引用函数名与调用点，行号易漂移不引用）。

## 一、问题定义：三端口径现状

| 链路 | 动作口径 | 代码事实 |
|---|---|---|
| 看板分析 / 扫描 / 推送 / 信号档案 | **最终动作**（含后处理） | `app.py`、`server/scan_engine.py`、`server/notify_service.py`（journal_hooks 挂后处理之后） |
| 模拟账户选股与执行 | **最终动作** | `server/sim_strategy.py` QushiV5Adapter：`signal_to_dict` → `_apply_signal_optimization` → Decision |
| 回测 / 评估 / 敏感性 / SCREEN_GATE | **原始动作**（`run_analysis` 直出） | `backtest/replay.py`：`engine(klines, ...)` 取 `result.action`，无后处理 |

后果：策略门（下降趋势 / M<30 → 观望）、软否决降级、盈亏比否决、M<40 降档等规则**只影响你实际看到和执行的信号**，历史统计评估的却是"没有这些规则的旧策略"。被评估对象 ≠ 使用对象——第一性原则 §2 明确要求"被评估对象必须与实际使用对象一致"。

## 二、为什么必须现在做

当前阶段（证据积累期）的每一期滚动评估都在为后续决策供料。口径不收敛，攒的样本回答的是错位的问题；先修口径，样本才有资格作为证据。

## 三、范围内 / 范围外

**范围内**
1. 后处理逻辑**单源化**为纯函数（行为冻结迁移）；
2. 重放**双口径落盘**（raw_action / final_action + policy 版本标记）；
3. 统计/敏感性**双口径并列披露** + 拦截分析小节；
4. 旧结果 policy 隔离，不混评；
5. 缓存失效机制（policy 变更 → 重算）。

**范围外（明确不做）**
- 不改策略门/后处理**规则本身**（只迁移，不改行为）；
- 不改 SCREEN_GATE 门槛**数值**（口径适用见 §4.5 开放问题）；
- 不做持仓级归因（剩余展望 #3 另立）；
- 不做参数寻优、不加新指标。

## 四、模块设计

### 4.1 后处理单源化（行为冻结迁移）

- 新建 `analysis/signal_postprocess.py`：纯函数 `apply_signal_policy(signal_data: dict) -> dict`，内容自 `server/signal_pipeline.py` 的 `_apply_signal_optimization` **逐字迁移**（该函数体当前不依赖 `klines`/`quote` 参数——以守护测试固化这一事实）；
- `signal_pipeline._apply_signal_optimization` 改为**薄委托**：保留原签名 `(signal_data, klines, quote)`，内部转调 `apply_signal_policy`；app / scan_engine / notify_service / sim_strategy 四个调用点与既有测试 stub 签名零改动；
- 迁移守护沿用 server 拆分先例（`tests/test_server_split.py` 模式）：固定输入集迁移前后输出逐字相等 + 四调用点端到端 smoke。

### 4.2 policy 版本：命名版本 + 内容哈希双轨

- `backtest/config.py` 新增 `SIGNAL_POLICY_VERSION = "policy.v1.gate"`（命名版本，人工维护，含义=当前后处理规则集）；
- `analysis/signal_postprocess.py` 提供 `policy_hash()`：模块源码 sha256 前 12 位，自动反映任何代码改动；
- 两者**同时**写入：signals.jsonl 每行、report.md / sensitivity.md / screen.md 报告头；命名版本供人读，哈希供机器比对（防"改了规则忘了升版本"）。

### 4.3 重放双口径落盘

`replay_symbol` 每个截窗：`engine(...)` → `signal_to_dict`（迁移纯序列化部分）→ `apply_signal_policy`，行字段：

| 字段 | 含义 |
|---|---|
| `raw_action` | 引擎原始动作（沿用现 `action` 语义） |
| `final_action` | 后处理最终动作 |
| `veto_reason` | 降级/拦截原因（无则空） |
| `policy_version` / `policy_hash` | 见 §4.2 |

- **事件集合锚定 raw 买入侧**（与现状一致），保证新旧可比；`final_action` 非买入的行保留落盘（供拦截分析），默认排除于买入侧统计；
- 事件集合差异**必须完全可由 veto_reason 解释**（验收 A4）；
- 缓存：`cache.json` 键值升级为 `{tail_hash: {"policy_hash": ..., "signals": [...]}}`；`policy_hash` 不匹配 → 该股重算（口径变更后一次性全量重算，报告披露重算规模）。

### 4.4 统计与敏感性双口径披露

- `report.md` 报告头披露 policy_version / policy_hash；汇总表**并列两套**：原始口径 / 最终口径（总体 + 按档位 × 视界，结构与现表同构）；
- 新增**拦截分析小节**：被降级信号（raw 买入 → final 观望/谨慎）笔数、其 r20/r60 绝对与超额均值，与最终口径对照——**只披露不结论**，n<10 标「⚠样本不足」；这正是第一性原则 §5 要求的"记录被过滤信号后续收益"；
- `results.csv` 增列 `raw_action / final_action / veto_reason`；
- 单调性 / sensitivity 主判据**默认最终口径**（可配），原始口径并列披露；sensitivity 事件集合仍按 §4.3 以 raw 为锚固定，逐组重贴双标签。

### 4.5 消费方口径（开放问题 Q1，实现前拍板）

SCREEN_GATE 与 advise 目前消费 results.csv 的买入侧合计。建议：**门槛规则自 I10 起改用最终口径**（与实际可交易动作一致），属预承诺规则变更——在决策日志留痕并披露，不追溯改历史门槛结论。未拍板前实现侧两套口径都产出，不阻塞。

### 4.6 兼容与隔离

- 存量 signals.jsonl 无 `final_action` → stats 识别为 `policy=legacy`，报告头标注「仅原始口径」，与新版结果不混评（沿用 pool.version 不一致拒绝模式）；
- 信号档案（journal）已是最终动作口径，本迭代**不动**；模拟账户已是最终动作，不动。

## 五、验收标准

- **A1 行为冻结**：固定输入集上 `apply_signal_policy` 与迁移前 `_apply_signal_optimization` 输出逐字相等；
- **A2 参数无关**：同一 signal_data 传不同 klines/quote → 输出相同（守护纯函数性）；
- **A3 四调用点不回归**：analyze / scan / notify / sim 既有测试全绿，stub 签名兼容；
- **A4 拦截可解释**：raw 买入但 final 非买入的每行 veto_reason 非空，拦截集合与 risk_codes / 趋势方向 / M 分可对账；
- **A5 policy 失效**：改动 signal_postprocess 一行 → policy_hash 变化 → 缓存失效重算 + 报告头更新；
- **A6 双披露**：report.md 双汇总表 + 拦截小节产出，n<10 纪律沿用；
- **A7 legacy 隔离**：旧结果与新版不混评，报告头披露口径状态；
- **A8 全量回归**：`python run_all_tests.py` 全绿。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 迁移引入行为偏差 | 逐字迁移 + A1 逐字相等守护 + 四调用点回归 |
| policy 变更触发一次性全量重算（750 根 × 全池） | 报告披露重算规模；重放本就幂等可重跑 |
| 双口径报告阅读负担 | 原始口径并列放次要位置，结论性判据单一（最终口径） |
| 门槛口径切换改变 SCREEN_GATE 历史结论可比性 | 决策留痕 + 报告头披露切换时点（§4.5） |
