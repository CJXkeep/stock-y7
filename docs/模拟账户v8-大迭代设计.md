# 模拟账户 v8 大迭代设计——全自动机器人 + 基准对比

> 日期：2026-09-01。状态：设计稿（先设计、后实现）。
> 前置：v6 账户内核、v7 配置与策略解耦（adapter 自描述 + 前端动态渲染 + 选股错峰）均已落地。

## 1. 定位（经用户确认）

**全自动交易机器人（虚拟记账）**：策略信号 → 自动成交 → 记账 → 组合级绩效，
人工只旁观——是「回测的实时版」。自用参考，非投资建议。

它要回答的核心问题：
1. 按策略实时执行，账户结果长什么样？
2. **跑赢大盘没有？**（新增：基准对比与超额收益）
3. 换策略时系统不耦合、配置不残留。

## 2. 范围（本轮做）

### 2.1 基准对比与超额收益（核心新增）

| 项 | 设计 |
|---|---|
| 基准可选 | 沪深300（000300，默认）/ 中证500（000905）；配置字段 `benchmark` |
| 数据层 | `fetch_index_kline` 扩展支持 000300/000905（secid=1.000300 / 1.000905，腾讯 sh000300/sh000905） |
| 记账 | `equity.jsonl` 每行快照追加 `benchmark`（当日基准收盘，与净值同日对齐；缺失记 `null` 并跳过该日基准计算） |
| 绩效 | 新增：**超额年化**（组合年化 − 基准年化）、**超额最大回撤**（相对基准）、**信息比率**（超额收益/超额波动×√252，样本≥20 披露）；既有年化/回撤/夏普/卡玛保留 |
| 前端 | 净值曲线叠加基准线（可切换沪深300/中证500）；组合指标卡新增「超额」区并标注基准代码；样本不足沿用披露纪律 |

### 2.2 策略切换可用化（v7 后端已就绪，本轮补前端）

- 配置面板新增「策略」下拉：由 adapter 注册表枚举可用策略（当前 `qushi_v5`）；
- 切换策略：`strategy_params` 按新 adapter schema 裁剪归一化（孤儿键清理已实现），
  「策略参数」区自动按新 schema 重渲染；
- 单策略不并行；`strategy` 字段与注册表机制继续作为多策略的地基。

### 2.3 全自动行为承诺与披露

- `enabled=true` 后：交易时段内按 `interval_min` 巡检、自动选股买入、自动止损止盈卖出（现状即如此）；
- 大页顶栏常驻显示「自动交易已开启」状态胶囊与最近巡检时间，降低"静默下单"困惑；
- 披露文案强化：全自动模式为策略直连执行，无人工确认环节。

## 3. 非目标（明确不做）

- 组合级风控熔断（账户回撤阈值暂停/减仓）——用户决策不做；
- 多策略并行——本轮不并行，架构继续预留；
- 实盘券商下单 / 资金划转；
- 日内 T+0 撮合、分钟级委托单；
- 重新拟合策略参数。

## 4. 模块设计

### 4.1 分层（沿用，不变）

```text
策略层(adapter，可插拔) → Decision 契约 → 账户内核(撮合/记账/绩效)
  → 服务编排(watcher/巡检/错峰) → 前端(大页 /sim.html)
```

### 4.2 基准对比数据流

```text
_snapshot_equity(state, now)
  ├─ 组合净值：equity = 现金 + 持仓市值（实时价估值）
  ├─ 基准值：fetch_index_kline(benchmark_code, count=1) 末根 close
  │    ├─ 与净值同日 → 写入 benchmark
  │    └─ 缺失/失败 → benchmark=null，本轮跳过（不中断巡检）
  └─ append_equity({date, ts, equity, cash, market_value, positions, benchmark})

compute_metrics(equity_rows, initial_capital, benchmark_code)
  ├─ 组合指标：年化/回撤/夏普/卡玛/胜率（现状）
  └─ 超额指标（有≥2 个同时含 equity+benchmark 的日期时）：
       rp = 组合日收益， rb = 基准日收益， re = rp − rb
       超额年化 = (1+Σre)^(252/N) − 1
       超额最大回撤 = max(1 − (1+累积re)_i / max(...))
       信息比率 = mean(re)/std(re)×√252（re 样本≥20 才披露）
       样本不足 → 显示「样本不足」不下结论（沿用 SAMPLE_MIN 纪律）
```

### 4.3 关键实现点

- `backtest/sim_account.py`：`compute_metrics` 增加基准参数与超额指标；equity 行 schema 增加 `benchmark`；
- `data/kline_fetcher.py`：`fetch_index_kline` 增加 000300/000905 映射（含 secid/腾讯前缀）；
- `server/sim_service.py`：`_snapshot_equity` 取基准并写入快照；`handle_sim_get` 返回 `benchmark_info`
  （代码/名称/最新值/覆盖日数）；配置白名单加 `benchmark`；
- 前端 `sim.js` / `sim.html`：净值图叠加基准线、指标卡超额区、策略下拉、状态胶囊；
- 配置：`benchmark` 属账户/引擎参数（与策略无关）。

### 8.2 实现口径（Agent 定，供实现对齐）

- **净值图基准线**：基准序列归一化到**净值首日=100** 叠加（同图对比）。
- **超额起点**：对齐序列第 1 点作为基准起点，从第 2 点起算日收益差 `re = rp − rb`；
  超额年化 `= (1+Σre)^(252/(N−1)) − 1`（与组合年化 `n−1` 口径一致）。
- **信息比率**：`mean(re) / std(re, ddof=1) × √252`（与夏普的样本标准差口径一致）。
- **基准值获取**：净值快照时 `fetch_index_kline(code, count=10)` 取末根 close
  （勘误：原定 `count=1`，实拉冒烟发现数据层对 <10 根返回有「脏数据丢弃」护栏，
  `count=1` 恒为空；取 10 根末根即可，盘中末根含当日实时 bar）；
  失败/指数非当日 → 写 `benchmark=null, benchmark_code=code`，该日跳过超额计算，不中断巡检。
- **空仓日定义**：当日快照 `positions == 0`。
- **配置**：`benchmark` 属账户/引擎参数（与策略无关），默认 `000300`，可选 `000905`，非法回退默认。
- **API 契约**：`GET /api/sim` 新增 `benchmark_info {code, name, latest, coverage_days, idle_days, idle_ratio}`；
  超额指标挂 `metrics.excess_*`（annualized / max_drawdown / information_ratio / coverage_days / idle_ratio / note）。
- **数据层**：`fetch_index_kline` 的 secid 规则已通用（`399*→0.*`，否则 `1.*`），
  000300/000905 自动映射 `1.000300`/`1.000905`，**无需改映射代码**；只需补测试 + 实拉冒烟。
- **compute_metrics**：签名扩展 `compute_metrics(equity_rows, initial_capital=None, benchmark_code=None)`，
  默认 `benchmark_code=None` 时行为与现状完全一致（向后兼容评估/重放调用方）。
- **切换策略的孤儿键清理**：沿用 v7 已实现的保存前 schema 裁剪（无需新增）。

| # | 代码设计决策 |

| Q7 | **年化分母用对齐序列点数 N**（与组合年化 `n−1` 口径统一）；基准连续缺失日不校准（缺口被对齐序列天然吸收） |
| Q8 | **`GET /api/sim` 的 `equity` 原样返回快照行**（含 `benchmark`/`benchmark_code`/`positions`）；前端从行内取基准归一化画线，单一数据源 |

## 11. 信号执行模式 close_nextday（收盘定档 · 次日执行，2026-09-02 落地）

> 背景：日线趋势策略的判定口径是「收盘确认」；旧「盘中实时选股」用实时价合成当日 bar
> 提前判定日线信号并立刻成交，与回测/信号档案的收盘口径不一致，且盘中信号抖动。
> 本迭代把**信号类决策**（买入 + 信号卖出）默认切换为收盘定档、次日执行，
> 价格类风控（止损/止盈/超期）维持盘中实时；intraday 模式保留可回退。

### 11.1 行为变化

| 环节 | 旧（intraday） | 新默认（close_nextday） |
|---|---|---|
| 买入 | 盘中每巡检周期用实时合成 bar 重算日线信号并立即成交 | 每交易日 15:05 后（当日未定档且为交易日）完整日 K 收盘口径定档 → 「明日买入清单」；次日交易时段按清单执行，盘中不再重算 |
| 信号卖出 | 盘中重跑日线信号 | 定档时对持仓收盘口径评估 → 「明日信号卖出清单」，次日执行 |
| 止损 / 止盈 / 超期 | 盘中价格触发 | 不变（仍盘中实时） |

### 11.2 关键实现点

- **执行节奏是策略属性**：StrategyAdapter 声明 `signal_mode`（close_nextday=收盘定档·次日执行 / intraday=盘中实时），
  `list_strategies` 暴露；服务层默认跟随当前策略（换策略自动切换节奏）。
  配置 signal_mode（auto 默认=跟随策略 / 显式 close_nextday、intraday 仅为高级强制覆盖）在账户/引擎参数层归一化，非法值回退 auto；
- 定档幂等键 = 日期（state.last_screen_date）；到点 = SIM_CLOSE_SCREEN_AT（默认 15:05，环境变量可覆盖）且当日为交易日（复用滚动评估 _is_trading_day_today）；
- 定档排在 K 线同步（15:30）/ 滚动评估（15:45）之前错峰；行情源限流（SourceThrottledError）时不清清单、不记幂等日期（下轮重试，避免半截样本）；
- 清单存 state.buy_queue / state.sell_queue（Decision.to_dict）；执行受持仓上限 / 单仓位 / 当日卖出去重 / 资金 / 涨停顺延约束；资金不足与满仓条目保留，超 SIM_QUEUE_STALE_DAYS（10 自然日）过期丢弃（定档连败自愈）；
- 适配器 evaluate/screen 增加 close_mode=True：跳过盘中合成 bar，走完整日 K + 收盘行情；
- 前端：配置卡「信号执行」下拉（跟随策略（标注当前策略生效模式，默认）/ 强制收盘定档 / 强制盘中实时）；新增「待执行计划」卡（明日买入档位/止损/目标/综合分、明日信号卖出清单）；状态行显示「明日买单 N · 明日卖单 M」，均按生效模式展示；
- 存量 bug 修复：_track_pending 对空 pending_buys 丢弃涨停顺延计数（or {} 拿到新 dict），改回写原 dict——该修复对 intraday 模式同样生效。
