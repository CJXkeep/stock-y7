> 状态：设计稿 **v5.1**（I7.x 五迭代交付后的实况回写 + I8.1 口径收敛计划，2026-08-22；前一版 v4 为第三轮 review 修订 2026-08-21）

> 代码事实核对日期：2026-08-22（v5.1；行号易漂移，优先引用函数名）

## 1. 设计目标与原则

### 1.1 目标
让使用者（自己）快速得到两个诚实的答案：
- **过去 2–3 年**，对自选核心池，每次出现的买入侧信号（强烈买入/买入），之后 **5/10/20/60 交易日**走势如何（胜率 / 平均收益 / 期望）；
- **从现在起**，真实出现的每个信号，事后（5/10/20/60 交易日）走势如何（信号日志）。

**定位：参考工具，不是自动交易系统。** 工具给出买卖点与计划作为参考，由使用者自行决策；评估的是**信号质量**（信号后价格通常往哪走），而不是"模拟完整账户按计划执行"的组合收益。

### 1.2 原则
1. **无前视是硬约束**：信号生成只用 T 日及以前数据；信号后的 N 日收益仅用于事后统计（评估本来就需看未来），绝不反向影响信号生成。
2. **不改变现有策略语义**：信号统计原样调用 `run_analysis`；信号日志只是对既有信号流的记录。
3. **可复现**：快照固定 + 无随机源；同一输入两次运行结果一致。
4. **独立样本**：信号去重（同一股票去重窗口内只保留首个）避免重叠样本高估可信度；报告标注去重口径与笔数。
5. **诚实**：快照防"历史数据回头看会变"；信号日志记录真实发生。
6. **实用优先**：不建组合状态机、不模拟资金/权益；能简化的不复杂化。

## 5. I7.2 信号日志设计（`backtest/journal.py` + app 钩子）

### 5.1 记录字段（一条信号一条 JSON 行）
```json
{
  "schema": "v5.journal.v1",
  "id": "uuid",
  "created_at": "2026-08-21T15:04:05Z",
  "symbol": "600519",
  "level": "day",
  "signal_type": "buy",
  "trigger_date": "2026-08-21",
  "action": "买入",
  "score": 68,
  "risk_level": "中",
  "entry": 1500.0, "stop": 1420.0, "target": 1650.0,
  "snapshot_close": 1500.0,
  "source": "main|chanlun_daily|chanlun_minute",
  "has_live_input": true,
  "notes": "..."
}
```
- `has_live_input`：是否用到 quote/flows/breadth 实时增强（与历史统计的"日线子集"口径区分）。
- `snapshot_close`：信号时刻的价格基准（盘中信号即信号时点价）；另设 `trigger_close` = trigger_date 当日**最终收盘价**，收盘后补记，保证与历史统计 close-to-close 口径可对照。
- 时间戳统一 UTC（ISO 8601 `Z` 后缀）。
- `schema` 字段标记记录格式版本：journal 为 append-only 且滚动归档，靠每条记录自带版本号支持未来字段演进。

### 5.2 补记字段（随使用自动追加）
```json
"followups": [
  {"asof": "2026-08-28", "close": 1520.0, "return_pct": 1.33, "horizon": 5},
  {"asof": "2026-09-04", "close": 1510.0, "return_pct": 0.67, "horizon": 10},
  {"asof": "2026-09-18", "close": 1480.0, "return_pct": -1.33, "horizon": 20},
  {"asof": "2026-11-18", "close": 1560.0, "return_pct": 4.00, "horizon": 60}
]
```
- 视界：**5 / 10 / 20 / 60** 个交易日；`return_pct = (close - snapshot_close)/snapshot_close*100`。
- 首次补记时同时回填 `trigger_close`（trigger_date 当日已收盘日线的收盘价）。
- **视界计数口径**：按**该股自身 K 线序列的第 N 根 bar 收盘价**计（停牌自然顺延）；周线/分钟信号的视界同样统一按日线 bar 计数。
- **补记数据源**：只用**已收盘**的日线数据；视界对应 bar 未收盘则不补记，禁止用盘中实时价充当视界收盘价。

### 5.3 落盘与去重
- `data/journal/journal.jsonl` 追加式（append-only，损坏行跳过并告警）；写入持有一把进程内线程锁（app 为 ThreadingHTTPServer，并发请求可同时触发钩子）；
- **全量落盘，不在写入时丢弃**：同一股票去重窗口（默认 10 交易日）内的重复同类信号照常落盘，标记 `"deduped": true`（窗口内首个为 false）；去重过滤在展示/汇总/统计层进行，规则与历史统计共用 `dedupe.py`——保证口径一致，且日后调整去重窗口时日志侧可重算；
- 精确去重键：`(symbol, level, signal_type, trigger_date)` 完全相同者只保留一条；
- `/api/scan` 全市场扫描结果**不入日志**（池外信号，口径显式排除）；
- 落盘失败**不阻塞**信号流程（try/except + log）；
- ~~归档策略：单文件超过阈值（默认 10,000 条）时滚动归档~~ **显式推迟（v5.1）**：单文件追加 + 损坏行跳过告警已满足当前量级；滚动归档待日志过万条再议。

### 5.4 采集点（app 侧最小改动，挂点清单）
- `app.py:494` 主链分析（单股，period=day/week）→ 最终 `action != "观望"` 落一条（strong_buy / buy / cautious_buy）；
- `app.py:494` 主链结果的 `sell_signals`（**仅 breakout「多头止损/卖出」**；主链 run_analysis 输出不含缠论信号，缠论只在下方独立端点采集；「空头平仓」在代码中拼入 buy_signals 偏多侧，见下方枚举表）→ 逐条落 sell 类记录；
- ~~`app.py:682` 批量分析~~ **更正（第三轮 review）**：该处实为 `/api/scan` 全市场扫描的工作函数 `_scan_one_stock`（`app.py:670`，app 中不存在独立的"批量分析"端点）——按上一条口径，扫描结果**不落日志**，此挂点取消；
- `/api/chanlun_daily`（app.py:609）→ 日线/周线缠论买卖点落一条（level=day/week）；
- `/api/chanlun_minute`（app.py:596）→ 分时缠论买卖点落一条（复用 `ChanlunSignal.type/price/time`，`level="minute"`）；
- **signal_type 枚举（实现照此映射，不随意扩展）**：
  | signal_type | 来源 | 统计侧 |
  |---|---|---|
  | buy | 主链最终 action=买入 | 历史统计计入（重放口径见 7.3） |
  | strong_buy | 主链最终 action=强烈买入 | 历史统计计入 |
  | cautious_buy | 主链最终 action=谨慎买入（后处理降级产物） | 仅日志；重放不含 app 后处理，历史统计天然不产生 |
  | breakout_exit | breakout「多头止损/卖出」(2N止损)，主链 sell_signals | 仅日志（统计对象只有买入侧 action） |
  | short_cover | breakout「空头平仓」——代码语义为偏多（signal_engine.py 拼入 buy_signals），按买侧如实记录，**不并入 sell** | 仅日志 |
  | chanlun_buy1 / chanlun_buy2 | 缠论一/二类买点（level 区分日/分） | 仅日志（历史统计只重放主链） |
  | chanlun_sell1 / chanlun_sell2 | 缠论一/二类卖点 | 仅日志 |
- **钩子挂点位置**：`_apply_signal_optimization` 与 `_localize_signal_text` **之后**——记录的是含否决/降级的**最终 action**；与历史重放（原始输出、无后处理）口径不同，报告头并列披露；
- 钩子只读结果、只写日志，不改策略/展示；落盘失败不阻塞主流程。

### 5.5 补记触发
- 每次启动/刷新时，对未完成（缺 60 日 followup）的记录按最新价补记；超过 60 日视界标记 `closed_at`。
- 逐条独立，不因某股停牌跳过后续。
- **已收盘判定（I7.2 实装）**：当日 bar 在本地时间 **15:30 前**视为未收盘而剔除，收盘后计入（`app._closed_daily_bars`）。
- **异步节流（I7.2 实装）**：补记为后台线程、600 秒节流；刷新后的首次响应可能尚未包含最新 followups（下次刷新可见）。

### 5.6 看板"信号档案"面板
- 列表：时间/股票/类型/信号日价/最新价/各视界收益，可按类型/股票筛选（**池只是筛选视图，日志记录全部信号**）；
- 汇总：总信号数、买入后 20 日上涨比例、平均收益、各类型分布；
- 仅展示，无"建议"措辞；前端新增只读面板；被窗口去重标记（`deduped=true`）的信号默认过滤，详情处可展开查看并提示「近期已记录」。

## 6. I7.3 核心池管理设计（`backtest/pool.py` + 看板面板 + app API）

### 6.3 看板界面

## 7. I7.4 历史信号统计设计（`snapshot/calendar/replay/dedupe/stats/report`）

> 定位：评估**信号质量**而非组合收益。无持仓状态机、无资金/权益/仓位。

### 7.1 范围
- 核心池：来自 `data/pool.json`（默认 20–40 只，可视化可换）；
- 区间：**2–3 年**日线，`qfq`；
- 统计对象：重放 `run_analysis` **原始输出** `action ∈ {强烈买入, 买入}` 的信号（`观望` 不入统计，但报告信号总体构成时计入分类数量；重放不含 app 后处理，故无 `谨慎买入`——该口径在报告头披露）。

### 7.2 快照（`snapshot.py` + `calendar.py`）
- 只含核心池 + 000001/000300（后者作参考环境/日历校验）；
- `manifest.json`：快照 id、生成时间、`pool.version`、股票清单+sha256、日历+sha256、每文件 sha256、`config_hash`；
- 校验（保留核心）：时间递增、无重复、缺口告警、OHLC 一致性、`source/adjust` 一致（不一致拒绝生成）；
- 快照生成后只读：统计前校验 manifest + `pool.version`，失效则拒绝；
- 抓取失败的股票记入 manifest `errors` 并从池内排除；报告披露"池内 N 只中 M 只可用"，缺失股票列名。
- **I8.1 收敛清单（v5.1 排定）**：`bars.jsonl` sha256 与 `config_hash` 入 manifest；OHLC 一致性违例的股票标记排除；`replay/stats` 对 `manifest.pool_version ≠ 当前池 version` **拒绝执行**（CLI `--allow-stale` 放行并在报告头披露 stale）。看板侧三态同步提示已于 I7.5 落地（`GET /api/snapshot-info`）。

### 7.3 信号生成（`replay.py`）
- 对每个交易日 t、每只股票：`run_analysis(klines[max(0, t+1-250):t+1], quote=None, flows=None, index_klines=idx[max(0, t+1-60):t+1], breadth=None, period="day")`；
- **滚动截窗与实盘同构（硬性要求）**：实盘分析恒定喂最近 250 根日K（`app.py:472`）+ 上证指数最近 60 根（`app.py:484`）；重放若喂入不断变长的前缀，MACD EMA 种子、250 日回看等长度敏感计算会漂移，导致同一日期重放信号 ≠ 实盘当时所见；
- **无前视**：仅用 ≤t 的 bar 生成 t 日信号；探测：注入"访问 >t 的 bar 即抛错"再全量重放；
- **窗口不足标记**：`t` 距快照起始 < 250 交易日时，信号标记 `warmup=true`（统计默认排除，或单独出"预热段"对照）；
- 增量缓存 `(symbol, tail_hash) → 信号`；40 股×750 日≈3 万次 ≈ 1–2 小时单进程，`--workers N` 并行（Windows spawn 需 `if __name__ == "__main__"`）。

### 7.4 信号去重（`dedupe.py`）
- 规则（历史与日志共用）：同一 `symbol` 在去重窗口 `D`（默认 10 个交易日）内，后出现的同类信号（同为买入侧）**只保留首个**；
- 参数：`--dedupe-window 10|0(关闭)`；报告同时给"去重前/后"数量，注明独立性限制；
- 实现：按 `(symbol, 信号日期)` 排序，遍历保留距上一保留信号 ≥ D 日的信号。

### 7.5 信号统计（`stats.py`）
对去重后的每个信号：
- 计算其后 **5 / 10 / 20 / 60** 个交易日收盘价相对信号日收盘价的 `forward_return`；
- 若区间不足（快照尾部）按可计算视界统计，缺失视界标 `n/a`。
汇总输出：
| 维度 | 指标 |
|---|---|
| 总体 | 信号数（去重前后）、各视界胜率（>0 比例）、平均/中位数收益、期望值（平均 forward_return）、标准差/标准误 |
| 拆分 | 按股票 / 按年份 / 按信号类型（强烈买入 vs 买入） |
| 展示 | 单股票明细 + 汇总表；CSV 全量 + Markdown 汇总 |

- **I8.1 收敛清单（v5.1 排定）**：标准差/标准误实装；任一分组 n<10 渲染「⚠ 样本不足，不下结论」；报告输出**去重前/后两套汇总表**（I7.4 仅交付全局双笔数 + 单一去重后汇总）。

- 无前视说明：信号生成与统计完全分离；`forward_return` 仅在事后计算，不参与任何信号生成。
- **样本量规则**：任一分组（股票/年份/信号类型）信号数 < 10 时，仅列数值并标注「样本不足」，不下结论。
- **口径提示**：统计（close-to-close）与单信号模拟（open-to-exit）口径不同，两者不可直接互比。

### 7.6 单信号独立模拟（`stats.simulate_one`，可选增强，无组合状态）
每个信号独立成一位"虚拟交易"，**不跨信号组合**：
- `entry_date = max(calendar.next(signal_date), executable_date)`；
- **本金假设（保留，可配置）**：`capital` 默认 100,000 元（CLI `--capital`），每个信号独立从满额本金开始（无跨信号状态）；
- **成交股数**：`shares = floor(capital / (entry_price × 100)) × 100`（整手向下取整）；`shares == 0`（一手买不起，如高价股）→ 记 `insufficient_capital` 跳过，报告披露数量与股票清单——这是真实资金约束的诚实反映，需要覆盖高价股时调大 `--capital`；
- `entry_price = 开盘 × (1 + 滑点 0.1%)`，0.01 元步进；卖出价对称 `× (1 − 0.1%)`；费用：佣金 0.025% 最低 5 元（双向）、印花税 0.05%（卖出）；
- 每日判定：
  - 同一日收盘同时满足 ≤`stop` 与 ≥`target`（双触）→ **保守记为止损触发**（报告标注该假设）；
  - 收盘 ≤ `stop` → 次日开盘卖出，记亏损；
  - 收盘 ≥ `target` → 次日开盘卖出，记盈利；
  - 60 个交易日（该股 bar）未触发 → 按第 60 日收盘结算；
  - 卖出日跌停 → 顺延至可卖；**买入日涨停 → 顺延至下一非涨停开盘日（上限 5 日），仍涨停记 `unfilled` 放弃**；顺延/放弃数量进报告；
- 输出：笔数、胜率、平均/中位净收益率、盈亏比（平均盈利/平均亏损）、期望值、持有天数分布、`insufficient_capital`/`unfilled` 计数。
- **明确**：无跨信号状态、无加仓、不模拟连续信号；结果仅用于"按计划管理单笔信号"的效果参考。
- **v5.1 实况注记（I7.4 实际交付口径）**：入场为 T+1 开盘价（暂未加滑点）；出场为**盘中触价即时成交**（low≤stop 或 high≥target 当日以 stop/target 价成交）——比本节草拟的"收盘确认、次日开盘卖出"更保守，**v5.1 起采纳为正式口径并回写本节**；涨停顺延暂无 5 日上限；无卖出跌停顺延；超时与数据截断未区分。除出场口径（采纳）外，其余全部列入 **I8.1 收敛清单**：滑点 0.1%（0.01 元步进、双边对称）、卖出日跌停顺延（连续 5 日第 5 日收盘强平标 `forced`）、买入涨停顺延 5 日上限→`unfilled`、`timeout`/`truncated` 区分、模拟汇总表（胜率/平均·中位净收益率/盈亏比/持有天数分布）。

### 7.7 输出（`report.py`）

## 11. 风险与开放问题

| 风险/问题 | 缓解 |
|---|---|
| 信号重叠、样本不独立 | 去重窗口（默认 10 日）+ 报告标注；独立性问题如实披露 |
| 免费源历史质量/复权 | 快照校验 + 与信号日志互相印证 |
| 自用也自欺 | 无前视 + 快照 + 真实验证三保险 |
| 核心池频繁变更 | 版本化：池变更→快照 stale→提示重新生成 |
| 实时信号含增强、历史含不含 | 日志 `has_live_input` + 报告口径标注 |
| 数据源/接口变动 | manifest 校验 + 便于重新生成 |
| 信号日志钩子影响主流程 | try/except 隔离，落盘失败只 log |
| 重放与实盘口径漂移（窗口长度/后处理差异） | 重放滚动截窗与实盘同构（250/60 根）；原始 vs 最终动作在报告头并列披露 |
| 并发请求同时触发日志钩子 | 进程内线程锁保护 journal 追加写 |

## 13. 已确认 / 待确认

**已确认**
- 本源定位：自用、实用、接受"未证实"；参考工具非自动交易系统；
- 核心池：可视化可配置、随时可换（`data/pool.json`，版本化）；

- **本金假设保留**：默认 100,000 元，`--capital` 可配置；一手买不起记 `insufficient_capital` 并披露。
