# 评估模块设计（信号评估体系 v1）

> 状态：设计稿 **v1.0**（2026-08-29，待评审后排入路线图）
> 关联：`docs/v5总体设计.md`（§1.1 定位 / §7 统计口径）、`docs/版本路线图.md`（I7.4 / I8.1 已交付，§八 v6 展望）、`docs/策略审核报告.md`
> 代码事实核对日期：2026-08-29（引用函数名，行号易漂移不引用）

## 1. 定位：评估什么、不评估什么

评估对象是**信号质量**：买入侧信号出现后 5/10/20/60 交易日，价格通常往哪走；分数档位是否携带增量信息；结论对参数扰动是否稳健。

明确不评估**组合账户收益**——对齐 v5 总体设计 §1.1 的定位（参考工具，不是自动交易系统）与版本路线图的"范围外"裁定。年化 / 夏普 / 回撤等账户级指标需要一条组合净值曲线，当前单信号独立模拟（`simulate_signal`）没有并发持仓与资金占用模型，算不出也不该硬算；此类指标归入 §5.5 条件项。

一条硬原则：**评估模块只测量、不优化**。不做自动调参、不做"按历史表现选参数"。综合分 75/60 分档阈值是历史 A/B 反推的产物（`signal_engine.py` 分档注释），评估的职责是把这件事暴露出来（§5.3），而不是用更多自由度把它掩盖掉。

## 2. 通用评估框架适配裁定

外部通用的"四层评估维度总表"（方向准确率 / IC / 夏普家族 / 过拟合防范）按本项目形态逐项裁定如下。裁定分六类：✅已有（换口径或原名）、🆕本版新增、🔁换口径等价物、⏸条件项（先建组合模拟才有资格谈）、⚠披露即可、❌不做。

| 通用维度 | 裁定 | 本项目对应物 |
|---|---|---|
| 方向准确率 (DA) | ✅已有（换口径） | 各视界 `win_rate`（`stats._summary`）——对择时工具，"信号后 N 日上涨比例"比泛化 DA 更贴切 |
| DA 单边市失真 | 🆕本版 | §5.1 超额胜率（相对沪深 300 同区间收益） |
| F1 分数 | ❌不做 | 引擎稀疏出信号，"召回率"需对全市场逐日标注机会集，个人工具无此价值 |
| RMSE / MAE | ❌不做 | 无价格回归对象；entry/stop/target 是计划价位非预测值 |
| IC / Rank IC | 🔁换口径 | §5.2 档位单调性——经典 IC 需横截面打分模型，本项目等价问题是"档位越高效应是否越强" |
| 累计 / 年化收益率 | ⏸条件项 | §5.5，需组合净值序列 |
| 最大回撤 / 夏普 / 索提诺 / 卡玛 | ⏸条件项 | §5.5，同上 |
| 胜率 | ✅已有 | 统计口径（forward return）+ 模拟口径（费后）双份 |
| 盈亏比 (Profit Factor) | ✅已有 | `summarize_simulation`（I8.1） |
| 每笔期望值 | ✅已有 | 模拟口径 `avg_pnl_pct` / `median_pnl_pct`（费后净收益） |
| 换手率 / 交易次数 | ✅已有（等价） | 分组笔数 + 10 交易日去重窗口 + `hold_days` 分布 |
| 资金容量与流动性 | ❌不做 | 个人资金规模（默认 10 万）无市场冲击问题 |
| 可解释性 | ✅天然满足 | 规则引擎 + reason 文本 + entry/stop/target 明示 |
| 参数敏感性 | 🆕本版 | §5.3 阈值敏感性扫描 |
| 样本外测试 (OOS) | ✅已有（口径） | 无前视重放即回测侧 OOS；**真实 OOS = 信号日志持续积累**（每天实盘落档的样本引擎没调过参） |
| Walk-Forward | ✅以实盘落档替代 | 规则系统无"滚动训练"；journal 前向样本 + 定期重跑 `stats` 即为本项目的滚动检验 |
| 前视偏差 | ✅已防 | 快照钉数据（sha256+config_hash）、重放 250/60 滚动窗口与实盘同构、warmup 排除 |
| 幸存者偏差 | ⚠披露即可 | 回放范围=当前自选池，退市/移出股不在内；报告头加口径声明（§7），不修全市场宇宙 |

## 3. 口径单一来源（所有指标共用）

以下事实口径全部已存在，新增指标必须复用、不得另立：

- **forward return**：close-to-close，按该股自身日线 bar 计数（停牌自然顺延），不足视界记缺失（`stats.compute_forward_returns`；视界 `config.HORIZONS = (5,10,20,60)`）。
- **胜率**：收益 > 0 的占比；超额胜率沿用同定义作用于超额收益（§5.1）。
- **去重**：同股同类信号 10 **交易日**窗口仅取首条（`dedupe.mark_window`，bar 序列日历）；统计给去重前后两套汇总，结论只取去重后。
- **warmup**：距快照起始不足 250 根的信号默认排除、单独披露（`--include-warmup` 保留）。
- **双 action 口径不可混用**：历史重放 = 原始 `run_analysis` 输出（强烈买入/买入/观望）；信号档案 = app 后处理后的最终 action（多出谨慎买入）。本文档 §5 全部作用于**重放口径**。
- **样本量**：分组 n < `config.SAMPLE_MIN`(10) 标「⚠样本不足」，不下结论。
- **离散度**：各分组 std/stderr（I8.1 起），只作人工判读辅助，不做显著性宣称（bootstrap CI 维持范围外）。
- **模拟口径**：T+1 开盘入场（涨停顺延上限 5 日→unfilled）、滑点 0.1% 双边对称不利、盘中触价即时成交（保守）、卖出日跌停顺延（连续 5 日第 5 日收盘强平 forced）、佣金 max(0.025%×金额,5元) 双边 + 印花税卖出 0.05%、timeout/truncated 区分（`stats.simulate_signal` + `config`）。
- **快照可信**：manifest sha256 + config_hash 校验、pool.version 不一致拒绝（`--allow-stale` 放行并披露）。
- **非因果声明**：统计为信号与市场环境的复合结果；自用参考，非投资建议。

## 4. 现状盘点（已交付的评估能力）

| 能力 | 位置 | 输出 |
|---|---|---|
| 总体/按动作/按年份/按股票 × 4 视界：n、胜率、均值、中位、std、stderr、样本不足标注 | `stats.aggregate` | report.md 分组表 + results.csv |
| 去重前后双汇总 | `aggregate` + `aggregate_raw` | report.md 两个总体表 |
| 单信号独立模拟汇总：胜率/平均·中位净收益率/盈亏比/持有天数分布/insufficient/unfilled/forced | `summarize_simulation` | report.md 口径声明 + 汇总行 |
| 信号档案事后补记 5/10/20/60 日收益（自身 bar 计数） | `backtest.journal` / `server.journal_hooks` | 看板信号档案、/api/journal |
| 每日速递历史战绩：最近 7 自然日到期收益 + 总体胜率（n<10 标样本不足） | `server.digest_service` | 看板每日速递块 |
| 无前视保障链 | `snapshot.verify_snapshot` / `replay` | 见 §3 末两条 |

缺口即 §5：**相对基准口径缺失**（绝对胜率在单边市虚高）、**档位增量信息未检验**（by_action 有数据、无判读）、**分档阈值敏感性未测**（75/60 是反推值）。

## 5. 新增设计

### 5.1 相对基准超额收益（P0，小）

**动机**：绝对 forward return 的胜率在单边牛市必然虚高（通用框架第一层点名的失真），分不清"信号强"还是"风大"。快照已含指数日线（`config.INDEX_SYMBOLS = ("000001","000300")`），补一个基准口径成本极低。

**定义**：
- 对每个信号每个视界 h：`r{h}_excess = r{h}(个股) − r{h}_bench`。
- **基准收益按同一自然日区间对齐**：个股 r{h} 的结束 bar 日期为 `end_date`，基准收益 = 沪深300 在 [信号日, end_date] 的 close-to-close（起点取 ≤ 信号日的最后一个指数收盘，终点取 ≤ end_date 的最后一个指数收盘）。不按指数自身 bar 计数——个股停牌顺延时，指数必须跨同样的日历区间，否则超额归因错位。默认基准 000300；开放问题见 §10。
- 超额胜率：`r{h}_excess > 0` 的占比（即"跑赢大盘的比例"——本项目形态下对 DA 失真的修正量）。

**落点**：
- `stats.compute_forward_returns(closes, t, horizons, bench_closes=None, bench_dates=None)`：bench 参数为 None 时退化为现行为。
- `aggregate` 每分组在 r{h} 旁增补 `r{h}_excess`（同一 `_summary` 结构，win_rate 语义变为超额胜率）。
- results.csv `RESULT_FIELDS` 追加 `r5_excess..r60_excess` 列；**存量结果文件不回刷**，重跑即得。
- 指数 bars 缺失/不足时：整体退化到绝对口径，报告头披露"本轮无基准，仅绝对口径"，不报错。

### 5.2 档位单调性检验（P0，小；经典 IC 的本项目等价物）

**动机**：经典 IC 衡量"预测分与实际收益的横截面相关"，本项目没有横截面排名，但有一个同构问题：**综合分档位（强烈买入 vs 买入）是否携带增量信息**——若档位与前瞻收益不单调，75/60 分档就是纯装饰，"强烈买入"不值得比"买入"多给仓位权重。

**判定**：数据全部来自现有 `aggregate` 的 `by_action`（§5.1 落地后含超额列），无需新计算：
- 逐视界比较相邻档（强烈买入 → 买入）的 `avg_return` 与 `avg_return_excess`；
- 输出相邻档差值及两档各自 stderr，供人工判读；**不做显著性宣称、不自动下"有效/无效"结论**（诚实原则：把 stderr 也自动化成判定规则等于引入新自由度）；
- 三态标记：`单调` / `不单调` / `⚠样本不足`（任一档 n < SAMPLE_MIN）。

**口径注意**：观望档无 forward return 样本，不参与；谨慎买入仅存在于最终 action 口径（日志），重放口径无此档——档位表按实际出现档位渲染，缺失档显式注明原因。

**落点**：`report.render_report` 新增「档位单调性」小节，置于"按动作拆分"表之后；§5.1 未启用的历史报告不受影响。

### 5.3 阈值敏感性扫描（P0，中）

**动机**：`signal_engine.run_analysis` 内联分档 `score >= 75 → 强烈买入，>= 60 → 买入`（注释自证"8/8 A/B 反推"）。这是策略审核报告"未经样本外验证"警示在参数层的具体形态——必须知道结论对这个反推值有多敏感。

**关键事实（口径干净的原因）**：replay 已落盘 `score` 字段；分档阈值变化**只改 action 标签、不增删信号事件**（是否为买入类由 signal_type 决定，与分档无关），去重与事件集合不变。因此扫描**无需重新 replay**，只重分档重统计，成本 = 每组阈值一次 aggregate。

**设计**：
- 新增纯函数 `action_from_score(score, th_strong=75, th_buy=60)`，`signal_engine.run_analysis` 改为调用它（行为不变，测试保证），扫描端复用同一函数——分档规则单一来源，防两处漂移。
- CLI：`python -m backtest sensitivity <snapshot_id> --thresholds "70,65" "75,60" "80,70" "85,75"`（默认含当前值 75,60 作锚点）。
- 输出 `sensitivity.md`（与 report.md 分离，不混入）：每组阈值 × 每视界 × 每档的 n/胜率/均值/超额均值 + 总体行。
- **判读指引**（写进文档与报告尾注，人工判读，不自动结论）：
  1. 档位单调方向在相邻阈值组间是否翻转；
  2. 提高阈值 → 事件减少 → 高档样本是否跌破 SAMPLE_MIN（结论自然失效的区间要标出来）；
  3. 总体 win_rate/avg 对扰动是缓变还是剧变。
- 复用 §5.1 超额列（若已落地）；未落地时先给绝对口径。

### 5.4 口径参数对照（P1，大部分已有）

I8.1 已产出去重窗口 D=5/10/15 对照并据此敲定设计稿 §13 默认值；视界 (5/10/20/60) 是产品语义不做扫描；`SAMPLE_MIN`、`CAPITAL_RATIO` 对照价值低。**默认不做**，留待真实疑问出现再补——防"为填表而扫描"。

### 5.5 组合级模拟（条件项，本版明确不立项）

**触发条件**（满足其一才立项）：需要回答"按全部信号实际执行的账户曲线长什么样"；或核心池信号并发密集到单信号独立模拟的假设明显失真。

**设计轮廓（仅记录，不承诺）**：信号按日期归并排队 → 并发持仓上限 N、单笔权重 w、同日多信号排序规则 → 成交口径复用 `simulate_signal`（滑点/涨跌停顺延/费率全套）→ 逐日净值序列 → 在净值序列上计算年化 / MDD / 夏普 / 卡玛。

**风险声明**：新增假设（并发资金冲突、部分成交、现金空闲收益）每一条都是过拟合入口，与"实用优先"原则冲突。已列版本路线图 §八 v6 条件项，本文档不展开。

## 6. 明确不做清单（总表裁掉项及理由）

| 指标 | 理由 |
|---|---|
| F1 / 召回率 | 稀疏信号无机会集定义；标注全市场逐日涨跌成本高、个人工具无决策价值 |
| RMSE / MAE | 无价格回归/点预测对象 |
| 经典 IC / Rank IC | 无横截面打分模型；等价物 §5.2 已覆盖 |
| 资金容量 / 市场冲击 | 个人资金规模不构成问题 |
| 年化 / MDD / 夏普 / 索提诺 / 卡玛 | 需组合净值；条件项 §5.5，不提前建 |
| bootstrap CI / 大样本分层 | 沿用 v5 范围外裁定；std/stderr 粗判够用 |
| 自动调参 / 按评估结果选参数 | 评估只测量不优化；防止把 75/60 的反推换成更多反推 |
| 全市场退市股宇宙修复 | 回放范围=自选池；报告头披露幸存者口径即可 |

## 7. 报告与展示层落点

- **report.md**：口径声明增三行——基准与超额口径（含自然日区间对齐说明）、档位单调性标记说明、幸存者口径（"回放范围为当前自选池，退市/移出股票不在内，结果仅代表池内经验"）；新增「档位单调性」小节。
- **results.csv**：`r*_excess` 列追加；旧文件不回刷。
- **sensitivity.md**：独立文件，不动 report.md。
- **CLI**：`python -m backtest stats`（指数可用时默认带超额，缺失自动退化并披露）、`python -m backtest sensitivity <id> --thresholds ...`。
- **每日速递不动**：历史战绩块口径刚在 891fc1c 做过可理解性优化，超额口径属统计深度口径，不进速递，避免块级复杂化。

## 8. 验收标准

- **A1 超额手算**：任取一信号，`r20_excess = r20 − r20_bench` 与手工按日历区间取指数收盘计算精确一致；个股停牌顺延案例中基准区间同步拉长。
- **A2 无基准退化**：从快照剔除指数 bars 后重跑，报告头披露"无基准"，绝对口径正常产出，不报错。
- **A3 单调性渲染**：构造两档均 ≥10 与任一档 <10 两种数据，三态标记（单调/不单调/⚠样本不足）正确；观望/谨慎买入缺档注明原因。
- **A4 事件集合不变**：任两组阈值下，参与统计的信号 (symbol, date) 集合完全一致，仅 action 分布变化。
- **A5 分档单源**：`signal_engine` 分档改为调用 `action_from_score` 后，现有信号分档回归测试不变；sensitivity 与引擎用同一函数。
- **A6 隔离与回归**：sensitivity.md 产出且 report.md 无污染；`python run_all_tests.py` 全绿。

## 10. 开放问题

1. **基准选择**：000300（宽基多头，v1 默认）vs 等权核心池基准（最贴"选股 α"，但引入组合收益新口径，违背实用优先）。v1 取 000300，等权池留 v6 与组合模拟一并考虑。
2. **日志口径的档位检验**：谨慎买入档只存在于最终 action 口径，样本随 journal 积累；是否对日志口径补做单调性检验（需先解决两口径不可混用前提下的独立统计出口），留待日志样本量上来后再议。
3. **分红口径**：个股与指数均为 qfq，分红回溯两边近似同口径，超额相减不另建全收益指数口径；若未来发现除权日附近超额异常，再升级为全收益基准并披露。
